# Developer Completion Report — AE-0564

Ticket: AE-0564 — Publish page heading and sticky header show different
carousel titles
Status: Dev Complete (pending PR CI)
Owner: Pedro

## Summary

Pedro saw the publish page `h1` and the sticky top bar disagree on carousel
`2fe43d2c`. Each surface picked its own label: both create breadcrumbs used
`project.topic`, the publish heading used `firstNonBlank([title, topic])` and
the workspace preview had a local title-or-topic helper that did not strip LLM
inline markup. One shared helper now owns the display-name rule —
`carouselDisplayTitle` in `src/lib/carousel-display-title.ts`: strip
`**`/`__`/`<strong>`-style markup, prefer the trimmed title, fall back to the
stripped topic — the same rule the workflow board card has applied since the
discovery work. The board adapter delegates its card title to the helper
instead of a second copy, and the workspace breadcrumb, publish breadcrumb,
publish `h1` and workspace preview (heading, hero and slide alt text) all read
from it.

## Root Cause

Four label call sites in the create flow implemented three different rules
over `title`/`topic`; when the LLM-written title differs from the topic, the
sticky header (topic) and the page heading (title) presented two different
names for the same carousel.

## Acceptance Criteria Implemented

- [x] AC1 Title set → publish sticky-header breadcrumb and page `h1` both show
  the stripped title.
- [x] AC2 Title blank (null, empty, whitespace) → both show the stripped

  set, topic otherwise).
- [x] AC4 Inline markup (`**bold**`, `__underline__`, `<strong>/<em>/<b>/<i>`
  with attributes) is stripped on every surface, matching the board card rule
  (unit-tested in the helper and pinned through the board adapter tests).
- [x] AC5 Workspace preview heading uses the same display title.

Surfaces intentionally left on the raw topic (they show the topic as a field,
not the carousel's name): the workspace summary card's labeled "Tema" row, the
brief step, and the cover prompt suggestions.
