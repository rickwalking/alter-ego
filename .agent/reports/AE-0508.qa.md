### 🟠 Warnings
1. **Retry is not "with the same inputs" after a reload** — `frontend/.../hooks/use-cover-generate-form.ts:106-113`, `components/cover-generate-parts.tsx:130`. The prompt/selection live only in component state and the failed row stores just the SHA-256, so after a refresh `canGenerate` is false and the "Tentar de novo" button is hidden (the test at `cover-generate-panel.test.tsx:218` explicitly blesses this). AC-3 asks for a retry on failure; the dev summary's "asks again with the same inputs" is an overclaim. Workaround exists (re-tick + retype), so not a blocker.
2. **Confirmation test does not assert xAI is named** — `cover-generate-panel.test.tsx:137-141` asserts only `count`/`carouselCap`/`monthCap` interpolation. AC-1/threat-note requires the dialog name xAI; the string exists in `en.json`/`pt.json` but a regression dropping it would not fail a test.
3. **No backend test for input bounds** — `api/schemas/carousel_cover_generation.py:24-42` enforces 1–3 photos and 3–500 chars; there is no test for 0/4 photos, whitespace-only prompt or >500 chars, and the `.feature` has no invalid-payload (422) scenario. Frontend covers the 3-photo/3-char side only.
4. **Cap-race mitigation is untested** — `application/services/carousel/cover_generation.py:217-222` checks + inserts after `lock_owner` (`SELECT … FOR UPDATE`), but every test runs on SQLite where that is a no-op (`modules/editorial/infrastructure/cover_generations.py:42-46`). The threat-note claim "two clicks cannot both pass the last slot" is asserted by design, never exercised. Suggest a Postgres-marked test or a two-session integration test in CI.
5. **`_fail_stale` in `start` has no test** — `cover_generation.py:218`. Only `usage()` (GET) is covered by `test_lost_run_is_reported_as_interrupted`; dropping the call in `start` would leave a restarted, still-`pending` carousel permanently blocked with 409 (killed only by a GET). Add: stale pending row → POST expects 202.
6. **Unreadable-file path collapses to "failed"** — `modules/editorial/infrastructure/carousel_cover_generation.py:89`: `Path.read_bytes` raises `OSError` (file deleted between listing and load) which is not `CoverAssetError`, so it settles `cover_generation_failed` instead of `cover_generation_photo_unreadable`, and `logger.exception` in `cover_generation.py:304` prints the local path. Low impact, but the code diverges from the dev summary's error mapping.
