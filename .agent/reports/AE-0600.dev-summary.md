## Developer Completion Report
Ticket: AE-0600 — Record why a carousel phase failed instead of losing it
Status: In Development (PR #342 open; the lead merges)

### Summary
Two autopilot POV carousels failed with `outline / failed`, an empty `error_message`, a bare
`workflow_failed(resume_validation_failed, ValueError)` event and a `succeeded` generation run.
`outline` is the phase the resume started from; the failure was in the content phase that runs
after the outline gate. Most probable cause (code evidence, logs gone): the EN slide translation
made one bare LLM call with no JSON retry and no fallback, and raised `en_translation_parse_failed`
on the first malformed or truncated answer. It now goes through the shared JSON retry policy and
the fallback model, injected by the orchestrator (`JsonRetryAnswers` through the `JsonAnswers` port)
because application code may not import agents. A failed resume now stores `<ErrorClass>: <code>`
on the carousel row, adds the code as `reason` on the `workflow_failed` event, and moves the
generation run to `dead_letter` (`workflow_failed`, cause in `last_error`) without a second owner
notice.
