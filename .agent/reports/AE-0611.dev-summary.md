# AE-0611 — dev summary

Status: Dev Complete

## Root cause

The translation runs once, before the fail-closed retry. `_build_review` rebuilds a re-drafted slide with the same
`translations_en`, and `_resolve_en_source` takes EN from there when the fresh draft has no `presentation_en`. Revise
is not affected (the whole deck is translated again) and the gate repair rewrites fields, not slides.

The rows are committed in the distribution step, and the localized copy reached them only when the phase ended, so the
retry and the gate repair ran with pre-retry rows. That final write also kept the old translation's `content_kind`.

## Change

- `refresh_redrafted_translations`: the re-drafted slides are translated from the PT the review will show, in one call.
  An unanswered slide loses its stored translation, so the gate blocks it.
- `review_content` (`content_review_step.py`, moved out of the runner with the rest of the review step): the rows
  follow the retry right away, after the scope is applied. `phase_artifact_runner.py` is 842 lines (880 on main).
- The re-translation catches only a failed call, `LLM_CALL_FAILED_ERRORS`: `ValueError`/`TypeError` (parse), the
  provider `APIError` (`PROVIDER_ERRORS`), `TimeoutError` and the model queue's `AllModelsUnavailableError` (moved to
  `domain/llm_errors.py` so the application layer can name it). Any other exception propagates.
- `_symmetric_translation` drops the stale `content_kind`.
- No gate, validator, limit, threshold or prompt changed.
