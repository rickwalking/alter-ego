# AE-0620 dev summary

Root cause: `get_db` wrapped `get_session` in `async for ... yield`. When a handler raised, `async for` left the inner
generator suspended, holding the session and connection until the garbage collector or loop shutdown. If `dispose()`
ran first, the connection could go back to an unreachable pool, which gives the CI `ResourceWarning`. This is a
production lifecycle bug, so the ticket has a `.feature`.

Fix: `get_db` opens the session with `async with`. No pytest setting or warning handling changes.

Tests: `test_get_db_closes_session_ae0620.py`, 4 of 5 fail on the old code; all 5 pass on the fix.

Tracer on the 741 tests before the victim, old against fixed: dispose with a checked-out connection 7 to 0; `get_session`
left to the GC hook 192 to 0; tests ending with a session close pending 29 to 0. 741 passed, 1 skipped on both.

Limit: the exact warning reproduces every time standalone, but no deletion occurred inside the real suite on this host.
