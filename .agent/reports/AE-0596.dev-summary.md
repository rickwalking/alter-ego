Status: In Development (local `backend:test` FAIL is timing-only; CI green; Dev Complete move left to the lead)

## Summary

Implements Pedro's decision (2026-11-02). `User` records the persisted fields assigned after it is built
(`changed_fields()`, mutators or direct assignment), and `PostgresUserRepository.update` writes only those, so a
profile or role edit never writes `hashed_password` or `token_version`. Every update path reads the user with
`get_by_id_for_update` inside the Unit of Work (admin edit and reset, `UserService.update` / `assign_role`, password
change). The admin edit locks the active-admin rows before the user row when it touches role or state, so admin
edits never deadlock. No schema change, no API contract change. PR #340, stacked on #336.
