## What changed

- `GROKBOT_API_KEY_SHA256` is a `SecretStr` on settings (`grokbot_api_key_sha256`). Empty means the autopilot API is disabled. The plaintext key is never stored.
- `require_autopilot_api_key` hashes `X-Api-Key` with sha256 and compares the hex digest to the setting with `hmac.compare_digest`. Missing or wrong key returns 401 `invalid_api_key` and a warning whose `reason` is `missing` or `mismatch`. The log line does not include the header or the digest. An unset or blank setting returns 503 `autopilot_api_key_unconfigured` before the key is checked. The dependency does not attach a user.
- The dependency is on the autopilot router only. The composition root mounts that router at `/api`. `GET /api/autopilot/signals` returns `{}` so the key can be enforced; AE-0352 fills the bundle.
- Autopilot routes share one slowapi bucket, `RATE_LIMIT_AUTOPILOT` (`10/minute`) under scope `autopilot`, keyed by client IP. The 11th request in a minute returns 429.

## Deviations

- Architecture §6 says "argon2/sha256" and the gap table names `GROKBOT_API_KEY_HASH`. This ticket and AE-0359 both name `GROKBOT_API_KEY_SHA256` and require sha256 plus `hmac.compare_digest`. Argon2 is not used.
- `GET /api/carousels` (the list) stays anonymous-public and returns 200. The key does not attach a user. 401 is asserted on routes that already require a user: `GET /api/documents` and `GET /api/carousels/{project_id}`. A call to the public list with the key matches a call with no key and no JWT.
- `GET /api/autopilot/signals` returns `{}` until AE-0352. This ticket only mounts the route.
- The router is imported from `bootstrap/app_factory.py`, not re-exported on the autopilot facade. Model registration imports the facade; exporting the router would make infrastructure depend on `rag_backend.api` through the shared slowapi limiter.

## Known risks

- `GROKBOT_API_KEY_SHA256` stays empty until AE-0359 wires the secret, so `/api/autopilot/*` returns 503 in any environment that has not set it.
- The shared limit uses slowapi's `get_remote_address` (the direct client), not `X-Forwarded-For`.
- Browser callers are out of scope. CORS `allow_headers` was not expanded to include `X-Api-Key`. The scout is curl.
