# Developer Completion Report — AE-0528

Ticket: AE-0528 — Admin edits a user's name
Status: Dev Complete (pending PR CI)
Owner: Pedro

## Summary

`PATCH /api/admin/users/{id}` accepts an optional `full_name` on `UpdateUserRequest` (Pydantic
`StringConstraints`: whitespace stripped, 1..255 chars, else 422). `UpdateUserInput.full_name` carries it and
`AdminUserHandler.update` applies it after the role/active changes through a new `User.rename` mutator (bumps
`updated_at` like `set_role`). The `users.full_name` column already existed and `PostgresUserRepository.update`
already persisted it: no DB or migration change. The edit dialog gains a labelled "Nome completo"/"Full name" field
(pre-filled, trimmed, validated before submit, sent only when changed); a 422 validation list maps to the same pt/en
message. The email stays fixed: no field in the dialog, none in the schema (a sent `email` is ignored).
`docs/architecture/openapi.json` regenerated. No Zod schema mirrors `UpdateUserRequest` in the schema-drift map, so
no Zod change was needed.
