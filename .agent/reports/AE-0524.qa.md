# QA Report — AE-0524 (daily recovery scan)

Verdict: PASS for review (rebased on main after AE-0523 #281 merged).

## Independent review (fresh reviewer, read-only)
No blockers. Confirmed: PgQueuer 1.6.0 runs schedules under `pgq run` (scheduler started next to the queue manager,
registry read after the factory yields); schedule rows are inserted `ON CONFLICT DO NOTHING` and claimed
`FOR UPDATE SKIP LOCKED`, so two workers or a restart run the scan once; the queue schema one-shot installs the schedule
table; `mark_attempted` is a real compare-and-set; nothing references `generation_runs` by foreign key, so the purge is
safe; `pgqueuer_log.created` is the right column; the alerts bot is a no-op without a token.
Majors fixed: (1) a failed run's retry could be retried daily: the run the scan queues carries a `daily_recovery`
ledger key and the scan skips it; (2) `run_stale` escalations could be revived forever (and never close): same key,
once per run. Minors fixed: a minimum age of 1 h for stale runs (the reaper may still be at them), one transaction per
stale revive, the batch limit applied after filtering tried rows, the "parados" count bounded to 7 days, PgQueuer's log
table name read from PgQueuer's settings.

## Tests
- Unit (12) and integration (9) — the integration file runs on Postgres 17 (isolated schema with a `pgqueuer_log`) and
  on SQLite; regressions for both "once" fixes and the minimum age.
