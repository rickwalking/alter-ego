### Summary
P0 of the carousel generation queue (Pedro's decision): protect the website from today's generation load with no
queue and no schema change except one index.

- One Chromium export at a time. `export_slot` (`infrastructure/external/export_lock.py`) takes a per-event-loop
  asyncio lock, then a session-scoped Postgres advisory lock (`pg_advisory_lock`, key `0x41455850`) on a
  dedicated connection, held for the whole `export_slides` call and released in a `finally`. Without a Postgres
  engine only the process lock applies. The slot logs `carousel_export_slot_acquired` with the wait in ms.
- Chromium is launched with `--disable-dev-shm-usage` and `--renderer-process-limit=1` (the backend container has
  the default 64 MiB `/dev/shm`).
- CPU-heavy image work runs in a worker thread (`asyncio.to_thread`): `_crop_border_artifact`,
  `prepare_carousel_export_assets` (PIL artwork optimization, also in the refinement re-export) and
  `PdfSlideBuilder.build` (img2pdf). PT/EN and standard/HD exports were already awaited one after another.
- Staggered autopilot starts: a queued run starts only when the newest start of any other run is at least
  `AUTOPILOT_START_SPACING_MINUTES` old (default 20, 0 turns it off). A start is the creation of the run's
  carousel project (`SqlStartHistory`: max `carousel_projects.created_at` over other autopilot runs), which
  the runner does right before `queued -> generating`; a run whose start failed retries without waiting for
  itself.
- `carousel_projects (phase_status, current_phase)` index: ORM model, alembic revision `f7a8b9c0d1e2`
  (Postgres-only, like `e6f7a8b9c0d1`) and the idempotent deploy one-shot
  `python -m rag_backend.scripts.carousel_phase_index --apply --verify` (`CREATE INDEX CONCURRENTLY IF NOT
  EXISTS` on an autocommit connection; an INVALID leftover is dropped and rebuilt), run by `deploy.yml` after the
  palette timestamptz step with the same never-block-the-stack shape.
