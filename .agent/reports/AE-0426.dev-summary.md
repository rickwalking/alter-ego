### Summary
Added a one-off, idempotent rebuild of AE-0422's hidden carousel-origin posts. The service selects
rows by the durable `ai_generation_metadata.hidden_bad_post` marker with `rebuilt_at` absent, reuses
each existing `blog_posts` row (CAS on `lock_version`, status set back to `draft`, publish stamps
cleared), and runs the AE-0425 writer pipeline to produce a `blog.v2` draft with cover/section images
and PT/EN quality scores. A successful (or partial) attempt stamps `hidden_bad_post.rebuilt_at`;
failures leave it unset so the next run retries.

After review: operators get `--only` (repeatable), `--limit` and an apply-only `--max-posts` spend cap
defaulting to 1, plus `--include-published`; published rows and carousels without `long_form_notes`
are skipped by default; the dry run performs the free material checks; the whole per-post body is
error-isolated and the summary always prints; a failed post exits non-zero; Langfuse is flushed.

After rebasing onto the new AE-0425 tip (AE-0424 slot-write path): `start_attempt` now replaces the
legacy body with `BlogDocumentService.initial_content()` and clears `featured_image_url` (the slot
path refuses non-v2 rows), the generation factory receives the row author (or the audit actor) so
slot writes record the same identity as the trace, and `retitle=True` lets the rebuilt draft take
the writer's title.

Standalone-process hardening (AE-0422 lesson): the CLI now imports settings, the DB, the checkpointer
and the bootstrap only after argument parsing, so `--help` works with no `SECRET_KEY`/`DATABASE_URL`;
an explicit `--dry-run` flag mirrors the default. A real-subprocess test runs
`python -m rag_backend.scripts.rebuild_hidden_posts --help` with the required settings removed and a
`--dry-run` against a file SQLite DB. All structlog calls use key/value events (no `%`-style
formatting). The runbook uses `docker compose exec backend ...`.

### Deviations
- The ticket names only the root script; the deploy image copies `backend/src` (not `scripts/`), so
  the implementation lives in `backend/src/rag_backend/scripts/rebuild_hidden_posts.py` and the
  ticket-literal root path is a thin delegating shim.
- `partial` image outcome counts as rebuilt and is stamped; only `failed`/lost-lease leaves
  `rebuilt_at` unset for a retry.
- Published rows are never silently unpublished: they are skipped unless `--include-published`, and
  the SQL attempt refuses them unless explicitly allowed.
- `--max-posts` is an apply-only cap (default 1) so the first prod run is one post; the dry run is
  never truncated by it.
- Missing `long_form_notes` is a skip (an ungrounded generation would be paid but useless).
- DB/mutation gates are deferred to CI per the worker rule; Docker is unavailable locally.
