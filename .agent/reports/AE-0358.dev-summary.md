## What changed

- The Instagram token lives in `integration_credentials` (`provider=instagram`), encrypted with Fernet under `CREDENTIALS_ENCRYPTION_KEY`. `cryptography` was already a dependency; no package was added.
- Startup seeds the row from `META_IG_ACCESS_TOKEN` when the row is missing and the key is usable. `expires_at` is now + 60 days and `refreshed_at` is now, so a fresh seed is not refreshed on the same boot. A second start does not replace the ciphertext.
- `InstagramTokenProvider.get()` reads that row. The AE-0357 publisher uses it. An empty token still fails the publish job immediately with `instagram_token_missing`.
- The worker runs a credential step before Instagram publish, once per America/Sao_Paulo day. A token at least 50 days old, or one whose `expires_at` is inside 10 days, is refreshed via `GET https://graph.instagram.com/refresh_access_token`. The new token and `expires_in` are stored.
- A failed refresh retries the next local day. The owner gets one Telegram message when expiry is inside 7 days or Meta returns error 190. The message links to Meta's Instagram Login business-login doc. The token is not logged.

## Deviations

- Seed also writes `refreshed_at = now`. The ticket required `expires_at = now + 60d`. A null `refreshed_at` is not treated as older than 50 days, so the seed sets the clock explicitly and a brand-new token is not sent to Graph immediately.
- Once per day is an in-memory Sao Paulo calendar gate on the process-lived worker adapter. A restart can run the step again the same day. The architecture table has no alert timestamp, so no column was added.
- The refresh URL is the unversioned `https://graph.instagram.com/refresh_access_token`, not `META_IG_GRAPH_BASE`. The client disables environment proxies and does not follow redirects. Transport errors become a status of 0 with the cause cleared so the query string is not retained.
- The owner alert is a direct Telegram `sendMessage`. `content.autopilot.ig_token_expiring` stays unused: AE-0355 only renders that event for an existing autopilot run, and a credential is not a run. The message includes `https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login`.
- A missing or invalid Fernet key logs `credentials_encryption_key_unusable` and does not register the Instagram publish tick or the credential tick. `get()` returns `""`, so a manual publish still fails with `instagram_token_missing`. The autopilot runner stays registered. Startup is not aborted.
- The publish provider opens its own session. A refresh committed on the worker tick can still be invisible to a publish `get()` in that same tick. The next tick sees the new token.
- "50 days old" is `refreshed_at` age `>= 50` days, so the acceptance criterion and the 51-day scenario both pass. The 10-day refresh window and the 7-day alert window are strict less-than.
