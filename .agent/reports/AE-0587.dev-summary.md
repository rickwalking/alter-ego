Ticket: AE-0587 — Users an admin creates must change the password at the first sign-in
Status: Dev Complete

## Summary

Implements Pedro's decision (2026-11-01). `AdminUserHandler.create` builds the new `User` with
`must_change_password=True`, whether the API generated the password or the admin typed it (the dialog's password is
optional, and a typed password is as known to the admin as a generated one, so every admin create is flagged, same
rule as a reset). Everything else is the AE-0511 machinery unchanged: login works, `/api/auth/me` reports the flag,
every other protected endpoint answers 403 `password_change_required`, and a successful change clears it. No schema
change, `POST /api/admin/users` response unchanged; its docstring (and `docs/architecture/openapi.json`) now says the
user must change the password at the first sign-in.

Other create paths checked and left unflagged: the bootstrap owner CLI (`scripts/bootstrap_admin.py`),
`UserService.create` (no HTTP caller), test fixtures; there is no sign-up route.

Frontend: the create-user dialog shows "The new user must change the password at the first sign-in." in the form and
"The user must change this password at the first sign-in before using the app." in the result (next to the generated
password, or the plain success message). pt/en keys `admin.createUserDescription`, `admin.createMustChangeNote`.
