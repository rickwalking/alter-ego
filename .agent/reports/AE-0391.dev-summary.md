### Summary
Each carousel LLM task now goes to its own model on the OpenCode Go endpoint (same key and
`x-opencode-session` header). `glm-5.3` is the automatic fallback. Slides are drafted in parallel.

- **Routing** (`build_chat_model(settings, role)` → `RoutedChatModel`):
  - **reasoning:** `LLM_MODEL_REASONING`, default `deepseek-v4-pro`, 240 s per call. Used for
    research synthesis, the outline, and rubric judging (`/rubrics`, `/sources`).
  - **fast:** `LLM_MODEL_FAST`, default `deepseek-v4.1-flash`, 120 s per call. Used for slide
    drafting (plus persona enforce), persona scoring, PT→EN translation, the caption, LinkedIn and
    refinement (new `fast_llm_service` container singleton), and the AE-0367 autofix
    re-translate (`EditorialWorkflowService.chat_model`).
  - **fallback:** `LLM_MODEL_FALLBACK`, default `glm-5.3`, 900 s per call.
  - Model ids exist only in settings; the defaults are in `infrastructure/config/llm_routing_constants.py`.
  - Unchanged: chat and RAG agents (no role, single `GLM_MODEL`). With `LLM_PROVIDER=anthropic`,
    or `glm` without a key, every role still gets ChatAnthropic.
- **Fallback triggers:**
  - any error except auth (401/403 are re-raised). This covers 5xx, other 4xx, and 429s once
    the OpenAI SDK's backoff retries are used up;
  - a timeout;
  - empty content (a tool call does not count as empty);
  - bad JSON after `llm_json_retry`'s re-roll and repair. The whole policy then runs once more
    on the fallback, keeping the bound temperature/max_tokens.
  - Each fallback logs a structured warning: `llm_fallback_used` or `llm_json_fallback_used`,
    with role, models and reason.
- **Langfuse:** the wrapper overrides `ainvoke`, so the inner model's run is the generation. It
  records the actual model, token usage is counted once, and it carries the tags
  `role:<role>` and `model:<id>`, plus `fallback:true` on a fallback, mirrored in metadata.
  No other tracing changes, to stay out of AE-0390's way.
- **Parallel drafting:** `gather_bounded` with `CONTENT_DRAFT_CONCURRENCY` (default 4) slots.
  - Results keep outline order.
  - The first error is raised only after every sibling settles, so no LLM call is orphaned.
  - Drafts already used only the other slides' outline context, never their drafts. That is
    kept, and near-duplicate re-drafting still runs afterwards.
  - Persona scoring uses the same limit.
  - EN translation was already one batched call, so it is unchanged.
- **Env:** `LLM_MODEL_REASONING`, `LLM_MODEL_FAST`, `LLM_MODEL_FALLBACK` and
  `CONTENT_DRAFT_CONCURRENCY` are in `deploy.yml` (secret, else default) and
  `docker-compose.prod.yml` (with defaults).
- **Docs:** `docs/backend/llm-model-routing.md` (with the benchmark table), a new
  "LLM Providers & Model Routing" section in `backend/CLAUDE.md`, and the root `CLAUDE.md`
  Model Selection Strategy table.
- No DB migration. No Python 3.12-only syntax (`asyncio.wait_for`, `zip(strict=True)` is 3.10+).
