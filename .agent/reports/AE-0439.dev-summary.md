## What changed (per AC)

- **F-07**: a Radar IA create stores `slide_count` 7 (v4 contract default, CTA included) instead
  of NULL (`resolved_slide_count`); `resolve_section_count` prefers the real deck size (the slide
  rows) over the legacy `slides_config` (6). ADR-0025 §Count documents that the CTA slide counts
  as a section.
- **F-12**: `_score_slides` stores every judge entry on 0-100 via the new pure
  `persona_score.on_hundred_scale_entry` (overall by itself, sub-scores together; the
  `unscored_ticks` counter is never scaled). Old raw rows still read scaled.
- **F-13**: the workflow-state response and the SSE review gate payload map `image_assets`
  container paths to `/api/carousels/{id}/preview/images/{file}` (URLs pass through); the stored
  state is untouched.
- **F-14**: every `GET /blog-images/...` 404 carries `Cache-Control: no-store`.
- **#155(a)**: the decode script reports `image_load_failed` for a missing/broken image,
  `image_decode_timeout` only for a real race timeout.
- **#154(A)**: the content-generation judge retry runs on the queue's next model (fallback judge
  via `as_fallback()`, a local `_FallbackModel` protocol — no new app→infra import).
- **#154(B)**: a passing gate with `rescore_pending` slides never approves: pending slides join
  `select_targets` at the content gate with no issues, the step fixes (re-scores, no rewrite) and
  WAITs until they are scored or the judge is declared unavailable.
- **#154(C)**: the WAIT fires only when the voice floor is the sole failure (no forbidden hits,
  no blocking quality rules, no engine refusal).
