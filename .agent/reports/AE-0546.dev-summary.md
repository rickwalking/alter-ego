## Developer Completion Report
Ticket: AE-0546
Status: In Development (pushed for the CI full gate)

### Summary
Approving carousel 5350e0ca from Telegram wiped its caption and the autopilot posted captionless. Root cause:
`create_generation_draft` (blog from carousel) created the carousel's canonical distribution home with
`distribution={}`; `PostgresCarouselRepository._overlay_distribution` overlaid `caption=None` on load; the public
release on approval (`release_public` → `repo.update_project`) saved `None` to the column and the home. Fixes: the
overlay keeps the saved column when the home has no value (an explicit `""` still wins; existing `{}` rows heal on
their next save); carousel drafts start with the carousel's copy; every Instagram publish path refuses an empty or
blank caption (`instagram_caption_empty`, run failed with a Telegram notice and retry); a workflow stuck before the
final review interrupt is parked (engine `is_parked_before_node`) and re-driven after the grace period.

Review round (PR #277): renumbered from AE-0542 (PR #274 holds it), then from AE-0545 (PR #279 opened first with it). The public release is now one targeted
`UPDATE carousel_projects SET is_public, current_phase WHERE id AND lock_version = seen` instead of saving the
whole carousel loaded earlier. A lost compare-and-set re-reads the version and retries up to 3 times, then raises
`version_conflict`: the route answers 409 and the Telegram/scheduled release reports "approve failed". Owner
publish on a claimed run (`publish_claimed`, atomic path) re-checks the caption. The release UPDATE is raw SQL,
so it carries the explicit run-epoch guard (`WHERE run_epoch = seen` + `StaleRunEpochError` for a stale run-owned
context) and is allowlisted in the raw-update gate with an AE-0315 survey entry (§2 #21). Read-only prod evidence query:
`.agent/reports/AE-0546.prod-evidence.sql` (the pi has no prod access; it needs a run on the droplet).

### Known Risks
- Until this deploys, any carousel with a blog draft created from it can lose its caption on approval.
- Pre-existing, unchanged: when a carousel has no `blog_markdown` yet, the publish route still builds it and saves
  the carousel it loaded (`crud.py` `repo.update_project`) before the release. After the content phase every
  carousel has `blog_markdown`, so this path is rare; a follow-up can make it a targeted write too.
- Carousel copy edits do not take part in the `lock_version` CAS, so the CAS guards the release against version
  bumpers (reaper, resume); the caption itself is protected because the release no longer writes it.
