### Summary
The checkpoint TTL reaper never deleted anything: it targeted `carousel-{id}` thread ids while the workflow keys
checkpoints by the bare project id, and it was never scheduled. It is replaced by a manual, signed-off, keep-latest
prune: `python -m rag_backend.scripts.checkpoint_prune` (dry run by default; `--apply --threads --backup`). The
workflow engine and the prune share `checkpoint_thread_id()`. Each pruned thread keeps its latest checkpoint per
namespace, the writes of it and of its parent and the blobs it references, so the workflow view still opens and a
parked run still resumes. A project is eligible only when finished, older than the TTL, not running, without a
pending republish, without an autopilot run that is not settled (queued, generating, owner-wait, rework, scheduled,
publishing, failed, escalated, publish_failed, awaiting_thesis), and rejected or published. Apply re-checks under
FOR UPDATE, writes an owner-only JSONL backup, checks its count, deletes in one transaction, and refuses no-ops and
partial deletes. Operator runbook: `docs/deployment/checkpoint-prune-runbook.md`.
