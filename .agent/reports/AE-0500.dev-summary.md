# AE-0500 Dev Summary — Analytics shows carousel publishing and Instagram insights

Date: 2026-10-30
Branch: `feat/ae-0500-analytics-carousels-instagram`
Ticket: `.agent/tasks/AE-0500-analytics-carousels-instagram.md`

## What changed

### Backend

- `modules/publishing/infrastructure/publishing_channels.py` (new, strictly
  mypy-checked) holds the channel-pluggable counters: a `PublishingCounter`
  protocol + `CHANNEL_COUNTERS` registry (`blog`, `carousel`) plus
  `channel_publishing()`, which reads each channel's publish events ONCE per
  request (bounded to the velocity window, and at least the last 30 days so
  per-month totals stay right) and derives both the per-channel counts and
  the weekly velocity from that single read; all-time `published_total`
  comes from a per-channel `COUNT`. `publishing_read_acl.project_analytics`
  consumes the typed `ChannelPublishing` / `AnalyticsVelocityWeek`
  projections directly (no more `dict[str, object]` round-trip).
- A carousel counts as published when it has an Instagram publish record
  (autopilot run or manual-publish ledger row with `ig_post_id`) — the same
  source `SqlInsightsStore` uses. Publish time = run `updated_at` / manual
  `claimed_at` (weekly-bucket granularity). Dedup per carousel; owner-scoped.
- `GET /api/editorial-analytics`: `published_this_week/month` are
  cross-channel sums; summary gains `channels[]`; velocity weeks gain
  `channels{}`. Owner/admin scoping unchanged (admin sees all, editor sees
  own). `average_views` removed (schema, projection, ACL, route, snapshot,
  OpenAPI artifact, frontend type) — it was a dead field nothing rendered.
- `GET /api/instagram/insights` gains `connector: {channel, configured,
  last_sync_at, stale, error}` — `last_sync_at` = newest stored `fetched_at`,
  `stale` = older than the 6h TTL, `error` = first Graph error code seen
  during the request's refresh. Top-level `configured` kept for
  compatibility. Domain: `InsightsConnector`, `ConnectorStatusQuery`,
  `connector_status()`; service tracks the first refresh error per request.
- Tests: unit (`test_analytics_publishing_channels_ae0500.py`,
  `test_instagram_connector_status_ae0500.py`) + integration
  (`test_analytics_channels_api_ae0500.py`,
  `test_instagram_connector_api_ae0500.py`); `.feature` files
  (`analytics_publishing_channels_ae0500.feature`, connector scenarios added
  to `instagram_insights.feature`); snapshot + OpenAPI regenerated.

### Frontend

- `analytics/page.tsx`: velocity chart extracted to `velocity-chart.tsx`
  with a channel picker (Todos/Blog/Carrosséis — buttons with `aria-pressed`
  and focus-visible rings, never colour alone); per-channel totals line under
  the velocity title; new `InstagramInsightsSection` below the chart.
- `analytics/instagram-insights-section.tsx`: totals over views, reach,
  shares, saves, follows, profile visits (summing only posts that report the
  metric — matches the API within rounding); a real `<table>` of per-post
  rows with a linked title, all metrics and `fetched_at`; connector-state
  banners: not configured (names the connector), stale (last sync time),
  sync error — stored numbers are shown with the warning, never silent zeros.
- Shared `instagram-kpi-tiles.tsx` and `insights-card-shell.tsx` extracted so
  the dashboard card and the new section don't duplicate (jscpd gate);
  `instagram-insights-card.tsx` refactored onto them (behavior unchanged).
- Zod schema gains the required `connector` block; `average_views` removed
  from the hook types; pt/en strings added (`dashboard.analytics` channel
  keys + new `dashboard.analyticsInstagram` namespace).
- Tests: section states, page channel filtering/keyboard, hook wiring, schema
  contract; existing tests updated for the removed field and the mocked
  section.
