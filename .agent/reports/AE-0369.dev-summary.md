### Summary
After every carousel post, the autopilot (and the owner's manual route) now posts one Instagram
Story that announces it. The owner's Telegram "published" notice says whether the Story went
out and which music to add in the app. The Graph API cannot add music to a feed post, so the
owner gets a nudge instead (option B).

- **Story image:** `story_pt.jpg`, 1080x1920 JPEG ≤ 8 MB, rendered with Pillow (already a
  dependency) from the PT `slide_1.jpg` (HD fallback). The slide is centred on a blurred,
  darkened copy of itself, with a caption band `Novo post no perfil ↑`. Pillow's bundled font
  (Aileron) has no ↑ glyph and the slim prod image ships no fonts, so the arrow is drawn as a
  shape. The file is stored in the serving root (the active artifact version, else the output
  dir) and is rendered again only when slide 1 is newer. Location:
  `modules/publishing/application/story_image.py` (the autopilot reaches carousel files only
  through the publishing facade).
- **Public route:** `GET /api/carousels/{id}/story-image/pt.jpg`, `image/jpeg`, gated by
  `is_public` (same as `slide-images`). It is 404 when the carousel is private or unknown, or
  the image was never rendered. Serve-only: the route never renders.
- **Story step** (`InstagramStoryStep`): runs in `_mark_published`, after the post id is stored
  and before the `publishing → published` transition, under the publish claim. On the manual
  route without a run, it runs before the ledger records the post id. So a crash leaves the
  run (or the ledger) unfinished, and the next attempt resumes the Story.
  - Idempotency is one `instagram_stories` row per carousel: a `published` row means no Graph
    call.
  - The container id is committed before `media_publish`. A container younger than 24 h is
    resumed. An older one is resumed only if its status read says `PUBLISHED`, so no second
    Story is posted.
  - Transient errors are retried, three attempts in total.
  - Permanent errors, a missing slide 1 / carousel, and any unexpected exception are stored and
    returned. The step never raises, so the run is still `published`.
- **Publisher:** `create_story_container` (`media_type=STORIES` + `image_url`), reusing
  `await_container` / `media_publish`. `fields` is now sent on every Graph GET, including
  `content_publishing_limit` (`fields=quota_usage,config`, AE-0368). Two helpers moved to
  `instagram_graph_payloads.py` to keep the publisher under 400 lines (389).
- **Notice:**
  - Line 1: `✅ Publicado: <permalink>` (Telegram links it, so a tap opens the post).
  - Line 2: `📲 Story: publicado` or `📲 Story falhou: <reason>`.
  - Line 3: `🎵 Adicione uma música pelo app (20s): sugestão: <style>`.
  - The extras travel on the outbox payload (`story_status`, `story_error`, `music_style`).
    Older events, and publishers that cannot post Stories, show only line 1.
- **Music map** (`story_constants`, `domain/music.py`): matched on whole niche words with
  accents stripped.
  - AI / IA / tech / LLM… → `lo-fi eletrônico / synthwave`.
  - Cybersecurity / cibersegurança… → `dark synth`.
  - Robotics / robótica… → `cinematic electronic`.
  - If no word matches, the image style decides: `comic_neon` → synthwave, `cinematic` →
    cinematic electronic.
  - Otherwise: `lo-fi beats`.

### Deviations / notes
- **Claim stale window:** the Story runs under the publish claim, so `MANUAL_CLAIM_STALE_MINUTES`
  now covers the Story's worst case too (`CLAIM_HELD_WORST_CASE_SECONDS` = publish worst case
  + 3 × Story worst case). It rises from about 73 to about 220 minutes, so a dead worker's claim
  is taken over later. Correctness (no takeover while the holder may still call Graph) wins.
- **Notice language:** the published notice is now in Portuguese for every run:
  `✅ Publicado` replaces `✅ posted`.
- **Expired `PUBLISHED` Story containers:** they are recorded as published with no media id.
  Stories are not listed on `/media`, so their id cannot be recovered.
- **Manual route without an autopilot run:** the Story outcome is recorded on the row and
  logged. No Telegram notice is sent, because the notice pipeline is keyed by run.
- **Pre-existing import cycle:** `rag_backend.modules.publishing` →
  `infrastructure.database.models` → autopilot → publishing. It only bites when publishing is
  the first import (it does on `main` too). Tests import through the normal order; not changed
  here.
