# Developer Completion Report — AE-0585

Ticket: AE-0585 — The last active admin can be deactivated
Status: Dev Complete
Owner: Pedro

## Summary

`AdminUserHandler.update` now runs one guard before any change: an ACTIVE admin who would stop being one (demoted,
deactivated, or both in one request) is refused unless another active admin exists. The count is the new
`UserRepository.count_active_by_role` (port, Postgres adapter, test fakes, contract test). A demotion raises
`LastAdminError` (409 `last_admin`, detail "Cannot demote the last admin", unchanged); a deactivation raises the
new subclass `LastActiveAdminDeactivationError` (409 `last_admin`, detail "Cannot deactivate the last active
admin"). The existing `last_admin` code is reused, so the dashboard's translated message already covers it. Demoting
an INACTIVE admin is now allowed (it does not reduce the active admins). Delete rules are unchanged (non-goal).

Frontend: the users page computes the only active admin from the FULL list (not the filtered rows) and passes it to
the table; the edit dialog of that admin disables the role select and the Active checkbox, both described by a pt/en
explanation (`admin.lastActiveAdminLocked`). A 409 `last_admin` still shows `admin.lastAdminError`, never the
English detail. No schema change; OpenAPI artifact regenerated (409 description only).
