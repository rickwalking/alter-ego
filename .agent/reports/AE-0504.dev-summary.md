### Summary
Pedro's Q12: the rubric is chosen per carousel in the create wizard (default = the default rubric); its
criteria go into the generation prompt and the scores are shown afterwards; no automatic rewrite.

- **Storage:** `carousel_projects.rubric_id` (FK to `quality_rubrics`) already exists in the ORM, the
  Alembic baseline and prod (checked read-only on 2026-10-22), so no schema change or one-shot is needed.
  `POST /api/carousels` takes `rubric_id`: left out = the default carousel rubric (the oldest when several
  are flagged), `null` = none ("Política padrão"), unknown = 404 `rubric_not_found`, not applicable to
  carousels = 422 `rubric_not_for_carousels`. The project response returns it (redacted on the public
  feed).
- **Drafting:** every content prompt (generic v6, Radar v7, POV, POV news) ends with the rubric block
  rendered from the new `carousel_rubric/v1/content_criteria.yaml` (name, description, guidance from
  the criterion prompt without its placeholders, scale, threshold as /100). The existing prompt versions
  are untouched; `ContentDraftAgent.with_rubric` scopes a copy of the agent per project.
- **Scoring:** after the drafts exist, `CarouselRubricJudge` (reasoning model, `carousel_rubric/v1/
  evaluate.yaml`, 0-100 stated in the prompt, structured JSON re-rolled/repaired by `ainvoke_json`)
  scores each criterion. `build_rubric_evaluation` clamps to 0-100, compares with the threshold as a
  percentage of the criterion's scale, weights the overall and rounds it (the Integer column). The
  evaluation goes into the workflow state's `rubric_scores` and replaces the carousel's single
  `rubric_evaluation_scores` row. Drafts that were not regenerated keep their scores; a judge failure
  leaves the run going without scores. Runs inside the content phase node, so the Langfuse trace is the
  project's (session_id = project id).
- **Final review:** "Qualidade" shows the rubric, the overall /100, each criterion's score vs its minimum,
  and flags those below it.
- **Delete guard:** `DELETE /api/rubrics/{id}` answers 409 `{code: rubric_in_use, carousels: [...]}` for a
  rubric a carousel uses.
- **Analytics:** the quality average counts only the caller's own content (carousels they own, posts they
  wrote) for non-admins; admins see all (the `blog_post_quality.py` pattern).
- **Layering:** the judge is injected through a domain protocol (`RubricJudge`) and the DB access goes
  through the editorial module ACL (`CarouselRubricAcl`), so the architecture ratchet is unchanged.
