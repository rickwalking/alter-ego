# Architecture Plan: AE-0556 — Carousel generation log

**Date:** 2026-10-26
**Status:** Ready for development
**Tier:** T3

## Goal and evidence

Provide the owner/admin generation timeline Pedro requested on `/dashboard/create/<id>`, independently of Langfuse. Code inspection shows `generation_runs` has current status and counters but no phase history; workflow audit/outbox payloads have no run correlation and can contain feedback or generation content; raw structured logs can contain prompts, SQL errors and paths. A new sanitized event stream is required.

## ADR check

ADR-0028 is required and included: this adds a persistent observability model, a cross-module recorder and a private read contract. ADR-0026 remains authoritative for queue state and migration-plus-one-shot deployment; events are derivative history, never queue state. ADR-0006 supports JSONB for bounded flexible details while query fields remain relational.

## Options

1. Reuse `generation_runs`, workflow audit and outbox reads. Rejected: phase durations and notable-step history do not exist, and raw payloads are unsafe.
2. Capture scoped structlog events into memory and flush later. Rejected: synchronous processors cannot await the database, background tasks can accumulate under memory pressure, and arbitrary log fields violate the content-free contract.
3. Add `carousel_generation_events` with explicit instrumentation and a stateless run-scoped recorder. Chosen: allowlisted fields, real phase timings, immediate bounded writes, no memory buffer and no Langfuse dependency.

## Data and write design

- Event fields: UUID id; run/carousel FKs with cascade; occurred-at; event type; nullable phase; outcome; duration; attempt; classified error/message codes; flat JSON details; nullable Langfuse trace id/URL.
- Details accept only named diagnostics such as ids, counts, status, finite scores, size, provider/model, language and retry delay. Strings, item counts and every fixed field are bounded; serialized details never exceed 4096 bytes. Unknown keys and all raw exception/content fields are dropped.
- The shared safe-failure helper returns exception type and classified code only. It never calls `str(exc)`, reads SQL/parameters or copies a DBAPIError message.
- A per-job `ContextVar` scope carries run identity and the recorder, not event lists. Autopilot instrumentation updates the scope's project id when a carousel is assigned. No scope means no write, so synchronous manual starts and unrelated exports remain unchanged.
- `SqlGenerationEventRecorder` sanitizes before opening an independent session, inserts one row, commits and returns. `asyncio.wait_for` bounds each write at 100 ms. `Exception` is contained with a safe warning; cancellation is not intercepted. No background tasks, batch arrays or cross-run state.
- Queue dispatch/start/retry/dead-letter/success, tracker begin/finish/failure, orphan recovery, phase artifacts, persona/content-gate summaries, image bridge, image reuse and PDF outcomes emit events. Tracker timing state is bounded by the existing 40-step job limit and discarded with the job.

## Read and UI design

- `GET /api/carousels/{project_id}/generation-log` uses the same owner/admin guard as the workspace, not the broader reviewer workflow guard.
- The store fetches `limit + 1` events ordered by `(occurred_at, id)` descending. The opaque cursor is the last event id and is resolved only inside the authorized project; keyset filters prevent duplicates/skips when newer rows arrive. Default 50, maximum 200.
- A page contains event DTOs plus only the referenced run summaries. It excludes run payloads, raw `last_error`, reviewer ids, PgQueuer internals and checkpoint data.
- The workspace query uses the existing SSE/poll-derived state signature to invalidate the log. No additional SSE connection or timer is introduced.
- Native `details/summary` elements group newest runs first; only the latest is initially open. Within a run, events are chronological and grouped by phase. Failure/warning text accompanies color, durations use a right-aligned tabular column, and load-more/trace links are ordinary keyboard controls.

## Migration and retention

- One Alembic revision chains from `d1b0cf9cd80d` and updates the single-head assertion.
- The existing `generation_queue_schema` command compiles idempotent table/index DDL from the ORM and verifies all new objects; deploy ordering already places it before application startup with fail-late handling.
- The daily recovery purge deletes `occurred_at < now - 30 days` before its existing run/log deletes. Cascades keep parent deletion valid. PostgreSQL tests cover old/recent rows, foreign keys and continued purge behavior.

## Testing and overhead evidence

- Red-first unit tests cover sanitization, planted secrets, DBAPIError, timeout/failure containment, event ordering and run/phase outcomes.
- SQLite and PostgreSQL integration tests cover API authorization, cursor races, retention, migration and idempotent one-shot behavior.
- React tests cover grouping, accessible disclosure, outcome text, load-more, trace links, PT/EN and invalidation without new polling.
- Measure at least 200 sequential inserts on the disposable test database and report count, total and mean/p95 recorder latency plus the timeout test. This is a relative regression measurement, not a production latency promise.

## Rollout and rollback

The one-shot is additive and idempotent; application code works with an empty table after deployment. Rollback is a code revert while leaving the harmless table in place; no data backfill or destructive down migration is required in production. Event write failures never block generation or startup.
