# Developer Completion Report — AE-0595

Ticket: AE-0595 — An admin password reset logs out the user's open sessions
Status: Dev Complete
Owner: Pedro Marins

## Summary

Implements Pedro's decision (2026-11-02). `User.reset_password` bumps `token_version` by one in the same Unit of Work
write as the temporary hash and `must_change_password`, so every token the user held before the reset answers 401
`Invalid or expired token` (on `/me` and `change-password` too, not just 403 `password_change_required`).
`AdminUserHandler.reset_password` now reads the user with `get_by_id_for_update` inside the Unit of Work (the
change path's row lock), so a reset and a concurrent change each bump from the committed version. No schema change,
no API contract change. The endpoint has no self guard: an admin resetting their own password is logged out and
signs in with the temporary password (no special case).
