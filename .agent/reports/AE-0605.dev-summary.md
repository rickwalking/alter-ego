# AE-0605 — dev summary

## Root cause

`first_cased_alpha`, the first-letter test behind `heading_not_sentence_case_en`, scanned the raw heading, so
on `<strong>Word ...` it returned the `s` of the tag. The check lives in `presentation_validation.py`; the
helper is in `presentation_validation_fields.py`.

The repair had the same blind spot: `_repair_heading_sentence_case_en` uppercased that same `s`. A correct
heading came back as `<Strong>Word`, and `<strong>word` came back as `<Strong>word`, which then passed the
check on the `S`.

## Change

- `first_cased_alpha` reads the text through the new `strip_html_tags` (`sentence_case.py`). The content keeps
  its markup.
- The EN heading repair calls the existing `repair_text_sentence_case_en`, which already skips tags. Without
  this, the fixed check would fire on `<strong>word` with no way to repair it.
- Severity, EN-only scope and every other validator are unchanged. `5 tips` still fires, as it did.

- Rule-fires regression: the rule fires on a plain, a `<strong>`-wrapped and a nested lowercase heading.
- Every test file that imports the touched code: 759 passed.
