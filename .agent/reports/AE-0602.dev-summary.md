# AE-0602 — dev summary

Status: Dev Complete

## Root cause

The translation is made once, and the fail-closed retry can change the PT draft after it.

1. `place_quote_cards` puts the card on the PT draft of a `pov_news` slide.
2. The translation copies that card to EN (`_with_pt_structure`, `with_en_quote_cards`). The model's answer never
   carries `insight`, so an EN card can only come from a PT draft that had one at that moment.
3. A slide that blocks the first review gets one re-draft. `_without_quote_card` strips the card from the fresh
   draft, and `_build_review` rebuilds with the same `translations_en`, so the card comes back in EN only.

A fresh scaffold draft recovers to `features:0`, against EN `insight:1`, which is the shape AE-0599 recorded for
slide 4 of 41c4f437. The prod checkpoint was not re-read: the proof is the code path plus the test through the
real chain.

## Change

`localized_slide_builder._without_en_only_card`: where the EN payload is built from a translation, an `insight`
the PT payload does not have is dropped and EN takes PT's `content_kind`. The existing recovery and gate repair
give EN the rest of PT's shape. No gate, validator, limit or threshold changed.

## Decisions

- Drop the EN-only card instead of re-translating: the chain has no translator, and a model call inside the
  retry brings new failure paths.
- Fix it in the builder, where every path joins a draft to a translation, so a checkpoint whose draft already
  lost the card is covered too.
- `test_content_gate_after_budget_ae0599.py` pinned this defect (the gate still reports slide 4). It now
  asserts no violation at all, and the matching AE-0599 scenario line changed with it.

## Proof

- `test_pt_en_same_cards_ae0602.py` (6 tests, `pt_en_same_cards_ae0602.feature`): 5 failed on the old code. The
  recorded shape and the retry path both failed with the EN `insight` still there. The sixth pins that a card PT
  still has stays in both locales.
- Fail-closed, gate-after-budget and same-cards tests together: 34 passed.
- 96 related test files (localized, translations, insight, quote cards): 1262 passed, 1 failed. The failure is
  not an assertion: it is an unraisable `ResourceWarning` (unclosed event loop) that pytest pinned on whichever
  test ran when the loop was collected, and the failing test moved between two runs of this hand-picked
  selection. Both tests pass on their own. CI's full `backend:test` is the verdict on this.
