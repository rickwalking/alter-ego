### 1. Advisory-lock release not cancellation/failure safe — **RESOLVED**
- `backend/src/rag_backend/infrastructure/external/export_lock.py:70-79`: the `finally`-unlock is gone. Clean exit only does `pg_advisory_unlock`; any `BaseException` invalidates the connection (the session ends server-side, dropping the session-scoped lock), then re-raises; `finally: close()` still runs.
- Tests `backend/tests/integration/test_export_slot_pg_ae0520.py:60-131` exercise all three paths against real Postgres: cancel (asserts holder count 1 → 0 and the next export acquires within 5 s), raised export error, and a failed unlock on a `pool_size=1, max_overflow=0` pool (holder count 0 after `DBAPIError`).
- Local run: `4 passed` for that file (all 4 PG tests), `20 passed` for the whole requested selection in 4.88 s.
- ⚪ Info (non-blocking): `invalidate()` inside the `except` can itself raise/mask the original error, and `except BaseException` also covers `KeyboardInterrupt`/`SystemExit`; `close()` in `finally` keeps cleanup correct, so no action required.

- Wiring confirmed: `runner.py:347` (`spacing.holds(run)`) and `bootstrap.py:344-348` (`minimum=timedelta(minutes=config.start_spacing_minutes)`).
