### 🟠 W1 — Mutation-risk boundary assertions (ticket AE-0628/0629, CI mutation will decide)
Likely surviving mutants and the assertions that kill each:
- `domain/repost_rules.py:110` `recent_drafts >= WEEKLY_CAP` → `>`: killed only by a test with **exactly** 2 prior live drafts asserting 422 `weekly_cap_reached`.
- `domain/repost_rules.py:106` `age_days(...) < MIN_AGE_DAYS` → `<=`: needs a Reel at **exactly** 60.0 days asserting it is eligible.
- `domain/repost_rules.py:135` `FINAL_MIN_SECONDS <= end-start <= FINAL_MAX_SECONDS` → boundary mutants at exactly 3.0 s / 90.0 s (feature/tests cover 2.0/91.0 — off-by-boundary may survive).
- `domain/repost_schedule.py:33` `start >= window.latest` → `>`: needs `now == window.latest` asserting "publish now, not in window".
- `application/repost_tick.py:112,115` `budget.renders > 0` → `>=`: needs a test asserting **exactly** one render per tick when 2+ drafts are due (TICK_RENDER_LIMIT boundary).
- `application/repost_tick.py:310` `> timedelta(minutes=30)` → `>=`: exact-30-min container timeout case.
- `domain/reels.py:111` `-1.0` sentinel → `1.0`: killed only if a test asserts unknown-metrics items sort **last**.
Fix: add boundary-value assertions in the corresponding suites.

### 🟡 S1 — Ownership check fails open on a missing `owner` field — `infrastructure/reels_gateway.py:180-184`
`_owned()` returns `True` when the Graph payload lacks `owner`. `MEDIA_FIELDS_ONE` does request `owner` (reels_constants.py:45-48) and the token is account-scoped, so this is defense-in-depth only — but "not Pedro's Reel → 404" would be stronger fail-closed. Fix: treat a missing `owner` as not owned, or document the reliance on Graph ACL.

### 🟡 S2 — Gherkin edge gaps (AE-0626/0628 features)
- No scenario for **401 without X-Api-Key** on the new `/reels`, `/reels/{id}/video`, `/repost*` routes (AC6 asserts "need the API key" — the dependency is router-level, `api/reels.py:75`, `api/repost.py:70`; middleware tests cover the mechanism, not these routes).
- No scenario for the **429 `rate_limited` envelope** on these routes (contract §"errors … includes the 429").
- No scenario for a **malformed Idempotency-Key** (length/charset) — covered by unit tests only.
Fix: add one negative auth/rate-limit scenario per feature.

### ⚪ Info
- `/r/{id}/{file}` is keyless with no rate limit by design (ADR-0031; `api/repost_files.py`). Path traversal is impossible: `file_name` is whitelisted via `PUBLIC_FILES.get` before any path join, `repost_id` is a validated UUID, status-gated by `SERVED_STATUSES`, uniform 404 prevents enumeration beyond unguessable UUIDs. ffmpeg is argv-list only, hook text via `textfile=` + `expansion=none` + protocol whitelist (`domain/repost_render.py:33-34,80-81,132-141`) — injection surface closed. SSRF: no user-supplied URLs reach the downloader/probe; sources are Graph-origin, https-enforced, size/time-bounded (`infrastructure/repost_video.py:91,140,152-158`). Telegram: constant-time webhook secret + `is_owner(update.actor_id, owner_chat_id)` (`application/owner_actions.py:217`); all tick transitions are compare-and-set (`application/repost_tick.py:275-280`) — racing taps can't double-move a draft.
