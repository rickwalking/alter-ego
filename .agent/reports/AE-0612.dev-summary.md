# AE-0612 — dev summary

## Root cause

`_validate_en_heading_case` compared the whole raw heading with the allowlist, so only a heading that is exactly
`iPhone` matched. `iPhone tips` and `<strong>iPhone</strong> tips` fired, against the `sentence_case.py` module doc.

Two repairs had the same gap. `slides_data_for_language` uppercases the first visible letter on every EN render, and
the heading repair ran on the heading-case code of an item title. Both turned `iPhone tips` into `IPhone tips`.

## Change

- `opens_with_allowlisted` in `sentence_case.py`, on the existing first-word test. The check uses it.
- `repair_text_sentence_case_en` and `slides_data_for_language` take an optional allowlist. `run_bilingual_export`
  passes the project policy's list.
- The heading repair ignores a heading-case code that an item title reported.
- The allowlist, severity, EN-only scope and every other validator are unchanged.

## Proof

- `test_en_heading_case_allowlist_markup_ae0612.py` (27 tests, Gherkin
  `en_heading_case_allowlist_inside_markup_ae0612.feature`). 6 of the first 25 failed before the fix.
- Rule-fires regression: the rule fires on plain and wrapped seeded headings, including `<strong>iphone</strong>`,
  `iPhoneX` and `<strong>eBayer</strong>`.
- Removing `_slide_field_codes` by hand makes the item-title repair test fail.
- Every test file that imports the touched code: 974 passed.
