### Decisions (no one to ask)

- **Hook photo missing → `failed`, not `escalated`.** The state machine has no `queued → escalated`
  edge, and an escalation assumes a carousel the owner can reopen. The run is failed with reason
  `hook_photo_missing` (Telegram: "📸 POV sem foto do slide 1: envie uma foto com o papel "hook"
  na sua biblioteca de fotos do dashboard. Nada foi gerado."). The next scout POV topic retries.
- **Pose-tag matching not built.** Nothing upstream (scout topic, run) names a pose, so the photo is
  the most recently used one, else the newest. Follow-up if the scout starts naming a pose.
- **No persona found → `None`, logged.** Radar IA runs keep running unscored (AE-0364); POV runs
  escalate at the content gate with `persona_not_scored`. Owner action: create the "Pedro" persona
  (R0) or set `AUTOPILOT_PERSONA_ID`.
- **Persona on every run.** The persona is attached to Radar IA runs too, so they are voice-scored
  as well (the AE-0364 floor applies to a real score); only the unscored case differs by mode.
- **"Signature line" = the persona's preferred phrases.** The persona model has no separate
  signature field.
- **Scout columns folded into `b1c2d3e4f5a6`.** Keeps `c2d3e4f5a6b7` the single head as the brief
  requires; safe because the revision is idempotent and prod applies the SQL by hand.
- **v3 scout routine edited in place.** The brief says to update v3 (not v1/v2); v3 has not been
  released yet. The README notes it is frozen from its first release on.
- **Wizard no longer calls `PUT /hook-photo` after create.** The create request binds and stages
  the photo; the endpoint stays for API clients. The unused frontend hook was removed.
