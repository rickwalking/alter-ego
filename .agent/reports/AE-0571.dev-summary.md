# AE-0571 dev summary

Root cause: `CarouselGenerationEventModel` has an FK to `carousel_projects`, but the deploy one-shot
runs in a process that never imports `CarouselProjectModel`, so compiling `CreateTable` cannot resolve
the FK. Tests passed before because the test conftest loads every model.

Fix: `schema._register_foreign_key_targets()` lazily imports `CarouselProjectModel` (an import at the top
of the module is circular through the shared model package) and is called from `generation_events_ddl`.
DDL output is unchanged (`CREATE TABLE IF NOT EXISTS`, same FKs/indexes); existing prod objects are untouched.
