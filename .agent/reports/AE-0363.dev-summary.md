### Summary
Hotfix for the 2026-10-14 prod incident (carousel 8e350d6e, autopilot run 9e06e958): the
autopilot approved the outline gate but the content phase never produced anything and the run
waited forever.

Root cause (verified in code, reproduced with the real service + graph before the fix): the
in-process driver DID execute the next phase, but inside the worker tick, on the tick session,
with the `lock_version` bump uncommitted for the whole LLM run and no run ownership (no
`in_progress`, no `run_started_at`, no heartbeat, no run events). LangGraph's checkpointer had
already committed the approved outline super-step (next=`content`), so when the content node
raised a provider error, `is_provider_outage` (every `openai.APIError`, incl. timeouts) made the
driver roll the tick back and return `PROVIDER_OUTAGE`, which the runner ignores, with nothing
logged. Checkpoint parked at `content/approved` with no interrupt; row rolled back to
`outline/awaiting_human`, lock 5, no run; `decide()` → WAIT forever. Re-sending approve there
would be worse: the null resume is consumed by the content gate's `interrupt()` and approves it
unreviewed (reproduced: lands at `design`).

Fix: approve, revise and re-drive go through the new editorial facade operation
`run_automation_phase` / `redrive_automation_phase`: in-flight guard, revise revision-cap
check, CAS, `mark_resume_in_progress`, commit, then the phase runs inline through
`execute_resume_run` (the wrapper the HTTP route schedules: epoch fence, heartbeat loop,
run.started/run.finished, own session, failure → row `failed`). Re-drive uses
`engine.continue_pending` = `ainvoke(None)`. `read_gate` reconciles checkpoint and row
(`domain/parked.py`): run in flight → wait/stale escalate; row failed → escalate
`phase_failed`; parked → wait 10 min, then REDRIVE (approved/in_progress) or ESCALATE
`engine_parked_no_run_in_flight` (Telegram via the escalation notice). Inline (not
fire-and-forget) was chosen so one run per tick holds and refusals map synchronously; the tick
transaction is committed before any LLM work.
