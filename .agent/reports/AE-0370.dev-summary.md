## Developer Completion Report

### Summary
The owner can now publish an approved carousel at once, or schedule it, from Telegram. The
Instagram Graph API has no native scheduling (`media_publish` posts immediately) and containers
expire after 24 h, so the schedule is our own queue: the time is stored on the run, and the
containers are created only when the run is due.

- **Approve** now answers with `🚀 Publicar agora` (`ap:pubnow:<run>`) and `🗓 Agendar`
  (`ap:sched:<run>`). Publicar agora is the old Approve path, unchanged: approve final review,
  `awaiting_owner → publishing`, release, then the worker publishes, posts the Story and sends
  the notice.
- **Agendar** shows the next 3 of `12:00` / `18:00` / `21:00` America/Sao_Paulo
  (`schedule_constants.SCHEDULE_SLOTS`). Each slot is at least 15 min ahead, and the list rolls
  over to the next day. Slot callbacks are `ap:at:<unix seconds>:<run>` (53 bytes). There is
  also `✏️ Outro horário`, which sends a ForceReply asking for `HH:MM` (today, else tomorrow) or
  `DD/MM HH:MM`. On 30/12, `02/01` means next January.
  - Invalid input, a past time, or a time more than 30 days ahead gets a clear Portuguese reply,
    and the prompt is asked again.
  - A slot button that has gone stale (its time has passed) shows fresh slots.
- **On a chosen time:**
  1. CAS `awaiting_owner → scheduled` with `scheduled_at`. A double tap therefore acts once.
  2. Approve final review (the workflow becomes `approved_for_publish`), with **no release**.
  3. Confirm with `🗓 Agendado para dd/mm HH:MM` plus `🚀 Publicar agora` and
     `❌ Cancelar agendamento`. A typed time is confirmed in a new message with the same buttons;
     `OwnerText` gained an optional keyboard.
  4. If the editorial approve is refused, the run goes `scheduled → awaiting_owner` and the
     review keyboard is shown again.
- **Due tick** (`ScheduledPublishSweep`) runs inside the worker's Instagram step, before the
  publish job.
  - A due run moves `scheduled → publishing` (reason `schedule_due`) and is released public. The
    existing job then publishes it on the same tick, with the quota check, containers, Story and
    notice.
  - The CAS, the publish claims and `ig_post_id` stop a second publish.
  - A run more than 10 min late still publishes, and the notice line reads
    `✅ Publicado: <link> (publicado com atraso de N min)`. The delay is measured from
    `scheduled_at` to the publish moment.
  - If the carousel is no longer `approved_for_publish` at its time (sent back, rejected, or
    missing), the run moves `scheduled → expired` (reason `schedule_withdrawn`) and nothing is
    published. The owner gets a dedicated expiry text.
  - If the release fails, the run moves to `publish_failed` with a notice that offers no Retry.
- **Cancel** moves `scheduled → awaiting_owner`, clears `scheduled_at`, and shows the review
  keyboard again.
  - **Publicar agora while scheduled** moves `scheduled → publishing` and releases the carousel
    at once.
  - Final review is never approved twice: `FinalReviewApproval` skips the resume when the
    carousel is already `approved_for_publish`, for example after a cancel.
- **`AUTOPILOT_DEFAULT_PUBLISH`** = `now` | `next_slot`, default `now`.
  - It is added to settings, `backend/.env.example`, `deploy.yml`
    (`secrets.… || 'now'`) and `docker-compose.prod.yml` (`${…:-now}`).
  - It is now a required name in the env-parity gate, and the new rule-fires test proves the
    gate fails when it is missing on either side.
  - With `next_slot`, Approve schedules the next slot directly and says
    `(próximo horário bom)`.
- **State machine:** `scheduled` is added with `awaiting_owner→scheduled`,
  `scheduled→publishing`, `scheduled→awaiting_owner` and `scheduled→expired`. The 72 h
  review expiry scans `awaiting_owner` only, so a `scheduled` run is never expired early
  (tested).
- **Safety:** only the owner allowlist can tap (tested for slots and cancel). Replies are still
  sent only after the commit. The manual web publish route refuses a `scheduled` run, because it
  is not `publishing`.

Code layout: the approve / publish-now / schedule handlers moved out of `owner_actions.py`
into `application/publish_choice.py`. They use the shared helpers `owner_replies.py` and
`owner_approval.py`, and `owner_actions.py` drops from 347 to 309 lines. The reply helper names
(`_answer`, `_edit`, `_finish`, `_tell`, `_apply`) are kept, so AE-0367's handler still fits.
- Pure rules: `domain/schedule.py`, `schedule_keyboards.py`, `schedule_ports.py`.
- Due query: `infrastructure/schedule_store.py`, which uses the `(state, scheduled_at)` index.
- Wiring: `bootstrap_schedule.py`.

### ⚠️ Migration (apply by hand on prod)
**Revision `a9b0c1d2e3f4`** (down `f8a9b0c1d2e3`, single head) is additive only:
- a nullable column `autopilot_runs.scheduled_at` TIMESTAMPTZ;
- the index `idx_autopilot_runs_state_scheduled_at (state, scheduled_at)`.

Prod deploys do not run Alembic, so the orchestrator must apply it **before** the deploy.
Without the column, every `autopilot_runs` read fails, because the ORM selects
`scheduled_at`. Equivalent SQL:

```sql
BEGIN;
ALTER TABLE autopilot_runs ADD COLUMN IF NOT EXISTS scheduled_at TIMESTAMP WITH TIME ZONE NULL;
CREATE INDEX IF NOT EXISTS idx_autopilot_runs_state_scheduled_at
    ON autopilot_runs (state, scheduled_at);
-- Only if prod tracks alembic_version at the AE-0369 head:
UPDATE alembic_version SET version_num = 'a9b0c1d2e3f4' WHERE version_num = 'f8a9b0c1d2e3';
COMMIT;
```

### Deviations / notes
- **Behaviour change for an old keyboard:** a review keyboard sent before this deploy still
  carries `ap:approve`. Tapping it now shows the publish-now / schedule choice; it no longer
  publishes at once.
- **Late delay:** it is measured at publish time, not at the due tick. A run that was on time
  but then waited out transient quota retries also reports its real delay.
- **Rework after a cancel:** final review stays approved in the editorial workflow (held at
  `approved_hold`). Rework uses the existing AE-0288 send-back path from there.
- **AE-0367 is not on `main` yet.** It also edits `owner_actions.py` (`OwnerActionDeps`, the
  handler map), `webhook_constants.py` and the review keyboard. Expect small textual merge
  conflicts; keep both sides' additions. AE-0367's fix-issues keyboard should keep the Approve
  button as `ap:approve`.
