# AE-0607 — dev summary

## Root cause (numbers in the ticket)

The fit attempt's own deadline (180 s, `asyncio.wait_for` in `copy_budget_fit._ask`) is shorter than the fast
role's path to its fallback (300 s per call; 3 transient tries + 2 s/4 s backoff = ≥ 906 s before the queue
moves to `qwen3.8-flash`). A primary slower than 180 s is cancelled mid-call and the fallback never runs.
Both prod failures took exactly 180 s (the outer deadline, not the 300 s role one). Latency could not be
measured from the Pi (prod ssh: publickey denied; no Langfuse keys); a healthy primary is estimated at
< 30 s for this request (≈ 2.5–3k input tokens, ≈ 400 answer tokens, 4096 cap at ~150 tok/s).

## Change

- `LlmCopyBudgetFitter`: with a fallback configured, the primary gets 120 s
  (`COPY_BUDGET_FIT_PRIMARY_SECONDS`); on timeout or unparseable JSON the same prompt goes to the fallback in
  the rest of the unchanged 180 s attempt (`copy_budget_fit_fallback_used` log, same Langfuse config). Other
  errors (already through the whole queue) are raised as before. Without a fallback nothing changes.
- Wiring: `PhaseArtifactRunnerConfig.budget_fit_fallback`; the orchestrator passes
  `fallback_runnable_for(roles.fast)` (no new agents → application import).
- Prompt `carousel_copy_budget/v3/fit_fields.yaml`: v1 template, `max_tokens` 32000 (v1 kept).
- No timeout raised; content gate, thresholds, gate repair and voice guard untouched.
