# AE-0607 — dev summary

## Root cause (measured by the lead in Langfuse)

Every fit call spent the v1 prompt's whole `max_tokens: 4096` on reasoning and returned empty content:
3 × `deepseek-v4.1-flash` (34.9 s, 37.8 s, 37.8 s), then the queue's fallback `qwen3.8-flash` (63.3 s),
173.9 s in all, until the step's 180 s `wait_for` fired. langchain-openai sends the bound value as
`max_completion_tokens` in place of the model's 32000 default, so 4096 is what the provider got. The gate
repair worked right after because it never binds its YAML's model block (it runs at 32000).

My first analysis (deadline order: fallback unreachable inside 180 s) came from reading the code and was
wrong for prod. The queue reached the fallback at +110 s. That fix (a 120 s primary window plus a fallback
call) is removed: at the measured ~65 tok/s, qwen's 60 s slot is ≈ 3.9k tokens, below the 4096 it already
failed with, and the split cut deepseek's room from ≈ 21k to ≈ 14k tokens.

## Change

- Prompt `carousel_copy_budget/v3/fit_fields.yaml`: the v1 template with `max_tokens` 32000; v1 kept.
- `EmptyFitAnswerError`: an empty answer is a named model failure (`copy_budget_fit_model_failed
  error=EmptyFitAnswerError`), where before it was an opaque `TypeError` from the parser.
- Routing doc: token caps on reasoning models, and the calls still bound under 4096 (cover ideas 1500,
  palette 2000), listed as follow-ups.
- Deadlines, the gate, the repair and the voice guard are unchanged.
