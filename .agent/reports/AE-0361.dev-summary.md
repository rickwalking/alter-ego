## What changed

- `POST /api/autopilot/topics` takes two optional fields per topic:
  - `image_style`: an enum of the five OpenAI presets, default `neo_anime`. An unknown value is a 422 for the batch.
  - `image_guidance`: at most 400 chars, control characters stripped, blank treated as absent, URLs rejected with `url_in_text`.
- New per-proposal rejections. The rest of the batch is still accepted.

  | Rule | Reason |
  |---|---|
  | `audience` not 1–3 words | `audience_not_simple` |
  | `niche` not 1–3 words | `niche_not_simple` |
  | `brief` over 600 chars | `brief_not_simple` |
  | `brief` shares no title keyword (casefolded, stop words in `BRIEF_STOP_WORDS` ignored) | `brief_off_theme` |

  The domain also re-checks `(openai, style)` against `SUPPORTED_IMAGE_COMBOS` (`image_style_unsupported`) as a drift guard.
- `topic_candidates` gains `image_style` (NOT NULL, server default `neo_anime`) and `image_guidance` (nullable). Revision `e7f8a9b0c1d2` sits on top of `d1e2f3a4b5c6` and is the single head.
- The runner's `ProjectSpec` carries `image_style` and the resolved guidance. The fallback template is anime references for `neo_anime`, style-neutral wording otherwise, plus `Background: <niche>-themed setting.` Pre-existing rows get the same fallback.
- `InProcessEditorialDriver.create_project` sets:
  - `image_model=openai`
  - `theme=auto`
  - `image_style`
  - `custom_visual_details` = the guidance
- The Telegram review keyboard message starts with `Audience: … · Niche: … · Style: …`. The values are read from the carousel row through the extended editorial `CarouselReviewRow`.
- Routine pack `ops/grokbot/grok-bot/v2/`:
  - `routine.md` adds the rules, the decision table and the `image_guidance` background rule.
  - `topics.example.json` gains the new fields and an on-theme brief.
  - `x-signals.example.json` is copied as-is.
  - The README points to v2. `v1/` is unchanged.
- Docs: `docs/architecture/grokbot-autopilot.md` §5.3 "Carousel defaults".

## Deviations

- `image_style` is a schema enum, as the brief specifies, so an invalid style is a batch 422 and not a per-proposal rejection.
- `brief` over 600 chars uses its own reason, `brief_not_simple`. The schema limit stays 800 so one long brief does not 422 the batch.
- Guidance is stored as sent (nullable). The runner resolves the template at project creation.
- The v2 `topics.example.json` is not a byte copy of v1. It shows the new fields, and its brief names the title so the example passes the new intake rules. `x-signals.example.json` is copied as-is.

## Known risks

- A v1 routine still running in prod will now see some topics rejected with `brief_off_theme` or `*_not_simple` until the owner pastes `v2/routine.md`.
- Keyword matching is exact-token. A brief that only uses a plural or inflected form of every title word (e.g. "agent" vs "agents") is rejected as off-theme.
