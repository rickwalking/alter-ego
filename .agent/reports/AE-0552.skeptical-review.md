# Skeptical Review — AE-0552

Status: changes required before production code.

## Blockers and required resolutions

1. Running-only status CAS is not an attempt fence. Add an attempt UUID in existing run payload, rotate it at every mark_running, and require it for counts/status/settlement writes and notice decisions. Cover old-attempt success/transient/permanent and ABA races.
2. PgQueuer update_priority does not accelerate retry jobs, and picked jobs retain dedupe keys. Add a conditional queued-job priority + execute_after update and an explicit stale picked-job fence/cancel/requeue handshake with integration tests.
3. Project-only locks can miss an early autopilot drive. Share the executor key builder and acquire autopilot-run plus currently attributed project keys, then re-read all state.
4. Failed-terminal replacements need durable successor/request identity in the replacement payload and an idempotent lookup after serializing on the old run.
5. Cap exclusion must be a durable NOT EXISTS predicate on the staged manual generation row, not autopilot state_reason which later transitions overwrite.
6. Cron and manual maintenance must use one deduped full control-job execution, lock, and summary path; independent function locks are insufficient.
7. Position order must carry pgq_job_id, priority, and retry eligibility: current running first, priority descending, dispatched job id, then undispatched creation/run id within class.
8. Existing panel and Telegram retry must delegate to the shared manual-recovery semantics rather than remain parallel paths.
9. Projectless unstaged rows are display-only until staged; recovery capability requires a project-backed orphan or existing generation run.

## Plan response

The implementation increments will incorporate every required resolution. No production code will rely on running-only CAS, update_priority for acceleration, project-only takeover locks, per-function maintenance locks, or synthetic projectless recovery ids.
