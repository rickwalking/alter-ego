With Langfuse at its 1280M cap instead of 993 the same instant is 2286 − 993 + 1280 = 2573 MiB (the earlier

Sizing rule: measured peak + 30 %, rounded up, with these exceptions:
- frontend: 384M rather than 256M: Next.js image optimization encodes AVIF for remote images, which the quiet
  sampling window probably never exercised.
- backend: the run peak above (1011 MiB) + 30 % = 1314 → 1344M. The reservation (384M) covers the web peak.
- redis: 128M rather than 64M: Redis has no `maxmemory`, carries Langfuse's queues and forks for AOF rewrites
  (copy-on-write), so a cgroup kill would drop the queue; the peak is 15 MiB.
- postgres: 384M covers `shared_buffers` (128 MB) plus work memory for both databases; the cgroup also charges
  page cache, which it reclaims before killing.
- Langfuse web: 1280M with a 1024 MiB Node heap (Pedro, 2026-10-24). The first cap (768M, heap 448 MiB) crash-looped
  Langfuse on prod after the deploy (1,050 restarts, `JavaScript heap out of memory`): its working set is heap, and
  its RSS peaked at 1105 MiB. 1280M leaves 256 MiB above the heap for native memory.

**After P1 the budget does not close.** With Langfuse web at 1280M, the worker at the measured run peak and the
current host overhead, the worst case is about 330 MiB over RAM (about 155 MiB over even with Langfuse at its measured
1105 MiB peak instead of its cap). P1 cannot go live on this box as sized without a further decision from Pedro, for
example: a smaller worker peak (no HD in the worker), Langfuse web off the box, or a bigger droplet.

Assumptions: the worst cases coincide (conservative); swap is not counted as headroom. The limits sum to more than
RAM on purpose: a limit bounds one service, the budget is the sum of peaks.

P1 sizing (Pedro, 2026-10-23): AE-0522 caps the worker for the measured run peak and lowers the backend to its web
peak + 30 % (512M) in the same change. Until AE-0522 merges the backend keeps its run-sized cap, because it still
runs the HD exports.

## Rollback per cap

Remove that service's `deploy.resources` block (or set the old value) and deploy; for ClickHouse also restore the
0.8 ratio in `clickhouse-config/low-memory.xml`, and for Langfuse drop `NODE_OPTIONS`. A container killed by its cap
shows `OOMKilled: true` in `docker inspect` and restarts on its own (`restart: unless-stopped`).
