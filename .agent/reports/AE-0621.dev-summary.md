# AE-0621 dev summary

Root cause: `ThesisPromptService.tick` read the 10 oldest `awaiting_thesis` runs by `updated_at`. The notice-ledger
write leaves `updated_at` alone, so 10 already-prompted runs still waiting filled that page and a newer run was never
prompted. On prod 11 runs were waiting and the "Gerar agora" Nvidia run was the 11th.

Fix: the tick scans every waiting run (`THESIS_SCAN_LIMIT` 10 -> 200, a guard only; waiting runs expire after 72 h).
Already-prompted runs are still skipped by the ledger key, so nothing is sent twice.

Tests: `test_thesis_prompt_scan_ae0621.py` uses a fake that honours `limit` oldest-first like the SQL repository. It
fails with the old limit and passes with the fix. `tests/unit/modules/autopilot`: 1146 passed.

Hotfix fast path: backend gates run individually (no Postgres locally, so test, diff-cover, migrations and schema-drift
run in CI); Python 3.11 import check ok; pip-audit left to CI.
