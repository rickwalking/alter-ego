# AE-0330 — Dev Summary

**Ticket:** send x-opencode-session header so glm calls stop failing with provider_unavailable
**Branch:** `fix/ae-0330-opencode-session-header`
**Tier:** T1 (prod-down hotfix)

## What broke

Prod carousel creation returned **503 `provider_unavailable`** from
`POST /api/carousels/{id}/workflow/start`. The generic detail hid the real cause,
which the AE-0318 logging did capture:

```
workflow_start_provider_error ... error="Error code: 400 - {'type': 'error',
 'error': {'type': 'MissingSessionID', 'message': 'Error from provider
 (Console Go): Request is missing x-opencode-session and cannot be routed
 efficiently.'}}"
```

OpenCode Go — which serves GLM 5.2, and prod runs `LLM_PROVIDER=glm` — began
requiring callers to send a conversation header. Our `ChatOpenAI` client sent
none, so every GLM call 400d, and `classify_provider_error` (AE-0319) correctly
mapped `openai.APIError` → 503. Their docs additionally ask API callers to
identify with their own user agent rather than the SDK default.

Not their outage, not a bad key — a new client requirement, so it would not have
self-healed.

## What changed

`chat_model_factory._build_glm_model` now passes `default_headers`:

- `x-opencode-session: alter-ego-<uuid4>` — minted once per client, so it is
  stable for the process lifetime (the chat model is a DI singleton), which is
  what OpenCode's routing and prompt-cache optimisation expects of a
  "conversation".
- `User-Agent: alter-ego/<app_version>`.

The Anthropic path is untouched and carries no OpenCode headers.

## Follow-on defect fixed here

Once GLM started answering, `POST workflow/start` ran to its full ~68.5s and
nginx 504'd at 60s — `location /api/` carried no `proxy_read_timeout` (unlike
`/api/health` and `/api/conversations/`, both 300s), so it used nginx's default.
The backend completed successfully and advanced the project; only the HTTP
response was lost. Both nginx confs now set 300s, applied live with `nginx -t`
+ reload. Cloudflare's ~100s edge cap remains — a slower generation needs
`workflow/start` made async (202 + poll), which is separate work.

## Third defect fixed here: AI response cache poisoning

Once the provider and proxy were fixed the run actually reached GLM, which
surfaced a pre-existing bug. `outline_agent` and `content_draft_agent` cached
the raw LLM response **before** parsing it. GLM returned empty content, `""`
went into the shared 1-hour TTL cache, and every subsequent retry re-parsed it
and failed in milliseconds **without calling the model** — the phase was
unrecoverable until the TTL expired.

`source_synthesis_agent` was already immune: AE-0318 made it cache only
`good_raw` and evict poison in `_parse_cached`. That fix was never applied to
the other two agents. Now all three parse first, cache only what parsed, and
evict unparseable entries on read.

Evidence (prod, 2026-09-14):

| attempt | reasoning tokens | duration | result |
|---|---|---|---|
| outline #1 | 31999 / 32000 | 376s | `content: ""` → failed |
| outline #2 (retry, cache hit) | — | <1s | failed, **no generation** |
| outline #3 (after cache clear) | 7548 | 127s | valid outline ✅ |
| content #1 | no usage reported | 82s | `content: ""` → failed |

The #3 result is why no model-config change ships here: the spiral is a
**tail event**, not a reproducible property of the prompt.

## Fourth change: GLM default 5.2 -> 5.3

User-requested after the trade-off was raised. Endpoint availability verified
before switching. 5.3 sampled at 1605-1808 reasoning tokens vs 5.2's observed
49-31999 range on the same prompt shape — a narrower distribution, not a
guarantee. The default is pinned by a test so it cannot revert silently.

**Open risk, not mitigated here:** no A/B against current output. Every
carousel, chat and RAG call changes model, and the exposure is the persona
voice-match (>= 70) gate on Portuguese copy. Watch the first prod carousels.

## Fifth defect fixed here: a failed phase looped the graph forever

With provider, proxy, cache and retry fixed, the run got further than ever —
all 11 LLM calls completed — and then spun for 14 minutes with **no LLM call**
until `GraphRecursionError: Recursion limit of 10007`. `content_phase_async`
returned early on `phase_status=failed` without `interrupt()`, and the gate
router only knew approved/retry, so the failed phase was routed back into
itself at 4 steps/s. Twice on one project (second time with every draft
present — resume never clears the stale checkpoint flag): 20,022 checkpoints,
700,676 writes rows, **791 MB** of prod Postgres.

Fix: failed → END on every gate; node decides on this run's artifacts, clears a
stale flag on success, stamps the failed phase; `needs_gate_reopen` re-enters a
failed phase on retry; explicit `recursion_limit=100` (legit max 20). Engine
regression: fail → END → retry → design gate; reverted routing raises
`GraphRecursionError`.

**Not done here:** pruning this project's 700k runaway checkpoint rows
(791 MB). `scripts/cleanup_carousel_checkpoints.py` only reaps whole threads of
COMPLETED/FAILED projects past TTL; this project is live. Needs its own pass.

## Open items for the reviewer

1. **The prod hot-patch must not be mistaken for the fix.** The running
   container was patched in place so generation works now; that lives in the
   container layer only and is lost on any recreate. This PR still has to merge.
2. **Session granularity.** One session id per process, not per carousel. Fine
   for correctness and for their routing; a per-conversation id would need the
   id plumbed through DI to a singleton client. Deliberately out of scope.
3. **`workflow/start` is synchronous and slow** (~68.5s live). The nginx fix
   buys headroom to 300s but Cloudflare caps the edge at ~100s, so this will
   resurface as a 524 on a slower run. Making it async (202 + poll on
   `workflow/state`, which the frontend already polls) is the durable fix.
4. **Empty model content still surfaces as `invalid_json` with a blank
   `error_message`.** The UI shows a failed carousel with no stated reason and
   the backend logs nothing. Treating empty content as a distinct retryable
   provider error (and populating `error_message`) is a follow-up, deliberately
   not folded into this hotfix.
5. **Unrelated test-isolation flake found.** mutmut's baseline runs the suite
   twice in one process; `test_palette_routes` makes 9 POSTs against a
   10-per-minute limit and the module-level slowapi `limiter` leaks counts
   across tests, so the second run 429s and breaks the mutation baseline.
   Reproduced with this ticket's test file excluded, so it is not from this
   diff. Deserves its own ticket (autouse `limiter.reset()` in
   `tests/conftest.py`).
