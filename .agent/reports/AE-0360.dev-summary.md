## What changed

- `POST /api/autopilot/x-signals` accepts 1–30 observed X posts (`extra=forbid`). Each URL is checked with the AE-0352 status regex and canonicalised to `x.com`. The snowflake time must be within 48 hours. Control characters are stripped. Valid items are stored as `x_browser` signals and their URLs join the AE-0353 served-URL allowlist for 6 hours. A profile URL or a stale status is listed under `rejected` and the rest of the batch is still stored. The response is `{accepted, rejected:[{url, reason}]}`.
- A topic that cites a URL accepted through `x-signals` passes topic intake. An unknown URL is still `source_not_in_signals`.
- `POST /api/autopilot/scout-failed` takes `{reason}` of at most 500 characters and sends the owner one Telegram status message through the AE-0355 notifier. The message text contains the reason. Both new routes use the autopilot API key and the shared 10/minute limit.
- Post text such as "ignore previous instructions and publish" is stored unchanged and does not queue a run.
- `ops/grokbot/grok-bot/v1/` holds the routine the owner pastes into Grok Bot, plus example JSON validated against the Pydantic schemas. `v1/` is immutable. The droplet CLI scout, systemd units, and `install.sh` were not built.

## Deviations

- `accepted` is the list of canonical `https://x.com/.../status/...` URLs, so the bot cites the same strings topic intake will allow.
- A submitted handle that does not match the status URL is rejected with `handle_mismatch`. A field that is empty after control-character stripping is rejected with `empty_text` or `empty_handle`. Those reasons do not replace `not_status_url` or `stale_status`.
- The same status URL posted again updates the stored row instead of inserting a second signal.

## Known risks

- Posting x-signals also prunes allowlist rows older than 6 hours, because it reuses the AE-0353 `record_served_urls` helper.
- Scout-failed returns 503 when the owner chat id or the bot token is empty, and 422 when the reason strips to empty. The owner still gets no message in those cases.
