# AE-0429 — Dev summary

Branch `feat/ae-0429-session-expired-logout-route` from `origin/main`. Frontend only.
Source: owner report on prod (2026-10-19), root cause verified by the orchestrator
(`GET /api/auth/logout` on prod → `405 {"detail":"Method Not Allowed"}`).

## What changed

1. **Route moved out of `/api`** — `git mv frontend/src/app/api/auth/logout/route.ts
   frontend/src/app/auth/logout/route.ts`. Behaviour is unchanged: clear the
   `access_token` cookie, best-effort `POST <backend>/api/auth/logout`, sanitize the
   `redirect` param, redirect to `/login?redirect=<safe>&error=session_expired`.
2. **401 redirect repointed** — `api-client.ts` now builds
   `${PUBLIC_ROUTE_PATHS.LOGOUT}?redirect=<path+query>`; `PUBLIC_ROUTE_PATHS.LOGOUT =
   "/auth/logout"`. `API_ENDPOINTS.AUTH_LOGOUT` (backend POST) is untouched.
3. **Middleware lets it through unauthenticated** — `isPublicRoute("/auth/logout")` and
   `PUBLIC_ROUTES` include the logout path (served by the next matcher, no token needed).
4. **Shadowed route deleted** — `app/api/auth/logout/route.ts` is gone; the URL inventory
   snapshot was regenerated (`/api/auth/logout` route → `/auth/logout` route, 27 routes).
5. **Regression guards** — `api-client.test.ts` asserts the 401 target is `/auth/logout`
   and **not** under `/api/`; `middleware.test.ts` asserts the path is public and outside
   `/api/`.
6. **Gherkin + tests** — `frontend/tests/features/session-expired-redirect-ae0429.feature`
   (happy, protocol-relative and absolute open redirects, missing param, backend failure,
   unauthenticated reachability). New `src/app/auth/logout/route.test.ts` covers the
   handler; the feature lists every test that references a scenario.

## Root causes

- nginx `location /api/ { proxy_pass http://backend/api/; }` (`nginx/nginx.conf.ssl:203`)
  forwards every `/api/*` request to FastAPI, so the Next route
  `app/api/auth/logout` never ran in prod. FastAPI only has `POST /api/auth/logout`, so
  the browser's GET received a 405 and the stale cookie survived.
- The other three `app/api` routes are shadowed the same way but currently resolve to
  same-path FastAPI endpoints; they are documented as a follow-up in the ticket with the
  exact backend routes that serve them. No deletion in this ticket.

## Decisions / deviations

- **Front-end path instead of an nginx exception**: immune to the proxy rule and deployable
  with the normal frontend build; the backend POST contract is unchanged.
- **Only the logout route moved**: the other three shadowed routes have no user-visible
  bug today (same-path FastAPI endpoints serve them); documented as a follow-up instead of
  an unrelated deletion.
- **E2E comment only**: `tests/e2e/auth-baseline.spec.ts` claimed the local
  `app/api/auth/logout` route only defines GET. The comment now says the POST is the backend
  logout and the cookie-clearing handler is `GET /auth/logout`; no assertion changed.
