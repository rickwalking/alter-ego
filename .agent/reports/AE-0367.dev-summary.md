### Summary
The owner can fix carousel quality issues from Telegram without editing, scripts or an LLM
re-run of a phase. The review message lists up to 5 issues from the AE-0366 validator over the
persisted slides (plus untranslated EN and lowercased proper nouns), and a 4th button
`🛠 Fix issues` (`ap:fix:<run_id>`) appears when something is fixable.

- **Webhook** (owner allowlist + `update_id` dedupe as before): clean carousel → callback
  answer "Nothing to fix", run untouched. Otherwise CAS `awaiting_owner → reworking`
  (reason `owner_autofix`), the fix is queued in the existing `rework_phase` column (marker
  `owner_autofix`, no migration), the old keyboard message becomes "Superseded by fixed
  version...". No repair runs in the webhook.
- **Worker tick** (`ReworkStep`, AE-0363 pattern): at final review it calls the editorial facade
  `run_owner_autofix` → `OwnerAutofixService.apply`:
  1. plan over the rows: AE-0366 `repair_casing` (first letter of every heading/body/item,
     pt-BR accents), proper nouns restored from the carousel's own vocabulary (mid-sentence
     capitals in outline/research/copy, Title-Case research titles only give distinctive
     tokens, trusted lowercase use vetoes) + a constants list + the policy list, never inside
     URLs/handles; empty content features from the slide's `key_points` (3-4 items, allowed
     icon per position); summary points from its key points or the content outline;
     `<strong>` rebuilt/balanced;
  2. one bounded EN re-translate (versioned prompt `carousel_autofix/v1/en_retranslate.yaml`,
     2 attempts, 90 s timeout each) for untranslated fields only; failure keeps the EN;
  3. under the shared project lock: lock-version CAS (always, so a fresh review revision is
     produced), rows via AE-0366 `project_localized_copy_to_database` (images, prompts, notes
     untouched), commit, checkpoint `localized_slides` + fresh validation report (casing
     markers dropped);
  4. republish via `republish_completed_carousel` (new artifact version, hero images reused);
     then the normal final-review stop moves the run to `awaiting_owner` and stages the new
     review (new album + keyboard, remaining issues listed, Rework always offered).
  A lost CAS / held lock keeps the intent for the next tick; nothing is written.
