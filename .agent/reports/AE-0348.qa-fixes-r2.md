## Per finding

| Item | Status | What changed | Tests |
|---|---|---|---|
| **R1** escalated-run starvation | fixed | An escalated run now goes to `rejected` in two cases: its carousel's phase status is `rejected` (owner reject in the web UI, or the stuck auto-reject), or 72 h pass with no fix (`escalation_expired`). The owner gets a Telegram notice in both cases (`KIND_ESCALATION_CLOSED`). An owner reject on Telegram sends no extra notice. The wake scan now runs through `RunRecoveryStore.escalated_for_check`: runs never checked come first, then the least recently checked, by `wake_checked_at`. `mark_checked` stamps that column and never moves `updated_at`. | `test_newest_fixed_escalation_wakes_behind_abandoned_ones`, `test_abandoned_escalation_is_rejected_after_72_hours[73-True/71-False]`, `test_rejected_carousel_closes_the_escalation[True/False]`, `test_closed_escalation_tells_the_owner[*]`, `test_owner_reject_on_telegram_sends_no_extra_notice`, `test_checked_runs_go_to_the_back_of_the_scan`, `test_only_escalated_runs_are_scanned` |
| **R2** SSRF redirect hops | fixed | New `GuardedDocumentFetcher` (`research_fetch.py`). It uses httpx with `follow_redirects=False` and `trust_env=False`, and follows at most 5 redirects itself. Every hop, including the first, passes `ScrapeRouteGuard.allows` (scheme, names, every DNS answer) before it is requested. The body is capped at 2 MB. Chromium now only renders that HTML with `page.set_content`, with JavaScript off and `page.route("**/*", block_all_requests)`, and it never navigates. The misleading `handle`/`record`/`verify` hop-routing code, its tests and its Gherkin were removed and replaced. | `test_redirect_to_loopback_is_refused_before_it_is_requested` (a real `ThreadingHTTPServer` on 127.0.0.1 returns a 302 to `http://127.0.0.1/internal`; the server log shows only `/start`), `test_public_redirect_chain_is_followed_hop_by_hop`, `test_relative_location_is_resolved_and_checked`, `test_more_than_five_redirects_are_refused`, `test_body_is_read_up_to_the_byte_cap`, `test_production_fetch_refuses_an_internal_url_without_a_request`, `test_production_client_follows_nothing_and_ignores_the_environment`, `test_every_page_request_is_aborted[*]`, `test_scraper_renders_the_fetched_html_without_navigating`, `test_unsafe_first_url_never_launches_browser` |
| **R3** wrong post and Retry re-publish | fixed | `recent_carousel_id(payload, since)` matches only the single album posted at or after the stored container creation time, minus 60 s of clock skew. With none or more than one, nothing is guessed. The container creation time now flows through `StoredContainer`, `finish_container`, `publish_container` and `recover_published_media`. The resulting `instagram_published_media_unknown` failure is terminal: `offer_retry=False`, no Retry button, and the text says the post may already be live and to check Instagram. The Retry handler refuses a run with that reason (`NO_RETRY_REASONS`). | `test_manual_post_before_the_container_is_ignored`, `test_two_albums_after_the_container_are_not_guessed`, `test_unmatched_published_container_fails_without_reposting` (now also asserts no Retry), `test_gateway_matches_the_album_posted_after_the_container`, `test_unknown_media_notice_has_no_retry_button`, `test_other_publish_failures_keep_the_retry_button`, `test_retry_is_refused_when_the_post_may_be_live` |
| **R4a** stale-claim takeover | fixed | Every Graph request has an overall `asyncio.timeout` deadline of 30 s. `GRAPH_PUBLISH_WORST_CASE_SECONDS` is derived from the existing constants: 45 requests × 3 tries × 30 s, plus 30 polls × 2 s, which is 4110 s. `MANUAL_CLAIM_STALE_MINUTES` is that time rounded up to minutes plus a 5 min margin, so 74 min. `claim_run` and `claim_manual` refuse a stale takeover while a container under 24 h old has no post id. A refused claim no longer blocks the next due run. A container older than 24 h is checked with `was_published` first: if it reports PUBLISHED it is recovered rather than recreated. | `test_worst_case_graph_publish_is_derived_from_the_retry_constants`, `test_stale_claim_window_outlasts_the_worst_case_publish`, `test_a_hanging_graph_request_ends_at_the_deadline`, `test_a_refused_claim_does_not_block_the_next_due_run`, `test_expired_container_that_was_published_is_recovered_not_reposted`, `test_expired_unpublished_container_is_replaced`, `test_stale_claim_takeover_waits_for_an_unknown_fresh_container[none/1h/25h]`, `test_a_released_claim_with_a_fresh_container_can_be_resumed`, `test_stepped_gateway_reads_whether_an_old_container_was_published[*]`, `test_atomic_gateway_never_reports_a_published_container` |
| **R4b** no-run crash between publish and ledger | fixed | When the gateway can resume, the manual path for a carousel with no run goes container first: `open_carousel`, then `save_manual_container` (committed), then `finish_container`. A failure or crash records the row as `failed` and keeps the container, so the retry resumes or recovers that container instead of posting again. The atomic path is unchanged for one-shot publishers. | `test_manual_container_is_stored_before_media_publish`, `test_manual_crash_mid_publish_keeps_the_container_for_the_retry`, `test_manual_container_is_persisted_and_blocks_stale_takeover`, `test_manual_publish_without_a_run_posts_once` (updated to the stepped path) |
| **R4c** approve race | fixed | The worker no longer fails a `publishing` run whose carousel is not yet public or not yet approved, as long as the run was updated within 300 s (`RELEASE_GRACE_SECONDS`). It skips the tick with `carousel_release_pending`: no transition and no misleading publish-failed message. After the grace window the run fails as before. | `test_not_public_inside_the_grace_window_waits[270-False/330-True]`, `test_precheck_is_permanent[*]` (now past the grace window) |
| **R5** notifier cursor skips | fixed | The event source re-reads the 10 minutes behind the cursor (`NOTIFY_RESCAN_WINDOW_MINUTES`). The notice ledger already skips delivered and exhausted events. `advance` only moves the cursor forward. | `test_event_committed_behind_the_cursor_is_read_again`, `test_events_older_than_the_window_are_not_read_again`, `test_advancing_to_a_re_read_event_never_moves_the_cursor_back`, `test_event_source_reads_oldest_first_after_the_cursor` (updated) |
| **R6** rule slips | fixed | `_transition_values -> dict[str, object]` is replaced by `_transition_statement -> Update`. `_resume_input` now returns `AutomationResumeInput`, exported by the editorial facade. The `cast(object, ...)` calls in `test_qa_r1_worker_notify.py` became casts to the real collaborator types or no cast at all, and `_state_event` returns `AutopilotOutboxEvent`. Both import-linter rule-fires tests now copy `src/rag_backend` to `tmp_path`, plant the seed there, and run `lint-imports --contract <id> --no-cache` with `PYTHONPATH` pointing at the copy. `src/` is never written. | `test_contract_fires_on_seeded_legacy_import[*]`, `test_contract_passes_on_the_unseeded_copy`, `test_facade_contract_fires_on_seeded_internal_import` (all assert the seed never exists in `src/`) |
| **R7** scout-failed cap race | fixed | `ScoutFailureLog.lock()` takes `pg_advisory_xact_lock` through the new shared `advisory_xact_lock` helper, which topic intake now uses too. The cap read, the Telegram send and the record all happen under the lock, and `report` always ends the transaction. | `test_concurrent_failures_deliver_at_most_the_cap` (real Postgres in an isolated schema: 5 concurrent posts deliver exactly 3; this failed with 5 before the fix), `test_cap_is_read_and_recorded_under_the_lock`, `test_suppressed_failure_releases_the_lock`, `test_empty_reason_never_takes_the_lock` |

The new Gherkin scenarios are in `autopilot_runner`, `autopilot_instagram_publish`, `autopilot_telegram_notify`, `autopilot_grok_bot_scout` and `url_safety_ssrf`. Spec `docs/architecture/grokbot-autopilot.md` §3/§4 is updated to match.
