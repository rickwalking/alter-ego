## Developer Completion Report
Ticket: AE-0555
Status: Dev Complete

### Summary

The generation worker's memory growth between carousel runs was page cache, not a Python heap leak. Each run
writes 116-224 MB of carousel files that the worker never reads again, and the cgroup charged that cache to
the worker until it hit the 1600 MiB cap (`memory.events max=83`, no OOM kill). The worker now flushes and
drops the cached pages of what it wrote: the slide export releases its output directory, and the artifact
activation releases the project output tree. Measured in the prod image, the run's files left in cache
dropped from 119-147 MiB to 0, the idle level is flat (348-383 MiB vs 461-493 before), and the cycle peak
dropped from 1109-1159 to 1029-1096 MiB. Chromium's HD render (about 650-700 MiB) is what bounds the peak
now. The cap and the restart policy are unchanged.
