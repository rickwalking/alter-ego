## 🟠 Warning Findings

1. **Advisory-lock release is not cancellation/failure safe** — `backend/src/rag_backend/infrastructure/external/export_lock.py:70-72`. `pg_advisory_unlock` and `connection.close()` are plain awaits in `finally`; `close()` returns the connection **to the pool**, it does not end the PG session (contrary to the module docstring at lines 7-9). If a worker is cancelled (deploy SIGTERM) or the unlock fails, the session-scoped lock can stay held on a pooled connection, and later `export_slot` calls block indefinitely on `pg_advisory_lock`. Recommend `asyncio.shield` around unlock and `connection.invalidate()` on the error path + a cancellation regression test. This is the one finding I'd fix before release.
2. **Start spacing is a non-atomic read-then-create** — `modules/autopilot/application/runner.py:347` + `modules/autopilot/application/start_spacing.py:26-41` + `infrastructure/start_history.py:29-40`. Two overlapping ticks (or a second runner instance) can both read an old `max(created_at)` and both create projects in the same instant. Single-worker deployment makes this unlikely, but nothing enforces it; no test covers concurrent ticks.
3. **Missing wiring assertion for the new setting** — `modules/autopilot/bootstrap.py:344-347` and `bootstrap/autopilot_worker_factory.py:94`. Tests only assert `Settings.model_fields[...].default == 20`; no test proves `settings.autopilot_start_spacing_minutes → AutopilotTickConfig → StartSpacing.minimum`. A mutant hardcoding `timedelta(minutes=20)` survives.
