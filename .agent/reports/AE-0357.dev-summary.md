## What changed

- An approved carousel in `publishing` is posted once. A stored `ig_post_id` becomes `published` with no Graph call. A container younger than 24 hours is polled and `media_publish`ed; the container id is committed before that call. A missing or expired timestamp creates a new container.
- `META_IG_GRAPH_BASE` defaults to `https://graph.instagram.com/v23.0`. Page tokens can select `https://graph.facebook.com/v23.0`. The publisher takes an `InstagramTokenProvider` (`get()`) so AE-0358 can replace the static setting.
- Transient Graph errors retry up to 3 times (backoff 60s, then 300s) and then `publish_failed`. Permanent errors, including Meta `36003` and a missing token (`instagram_token_missing`), fail immediately. The owner notice is an outbox row `content.autopilot.publish_notice` with `offer_retry` and callback `ap:retry:<run_id>`. AE-0355 delivers it.
- `GET /api/carousels/{id}/publish/instagram/status` returns `{state, ig_post_id, permalink, error}`. No run is `unpublished`. The existing POST stays idempotent and still calls `publish_instagram` when the injected publisher is not the real Graph client.

## Deviations

- Architecture §4 has no container timestamp. `updated_at` moves on every retry, so the 24h reuse rule uses a new nullable `ig_container_created_at`. A null timestamp is not reusable.
- The owner notice is the outbox event `content.autopilot.publish_notice`, not a Telegram call. AE-0355 owns delivery. Retry is `offer_retry` plus `ap:retry:<run_id>`.
- The token port is `InstagramTokenProvider.get()`. AE-0358 owns encryption and refresh. A missing token fails immediately with `instagram_token_missing`.
- The manual route keeps calling `publish_instagram` when the publisher is not `MetaInstagramPublisher`, so the existing AsyncMock route tests stay green. A real publisher uses the stepped job.
- A permalink fetch failure still marks the run `published` with a null permalink. The post is already live, so the next tick must not call `media_publish` again.
- Quota of 0 is transient (`content_publishing_limit_exhausted`). Local pre-checks (not approved, not completed, not public, slide count, missing project, missing base URL) are permanent and do not increment attempts.
