drafts with `persona_scores = {}` and the autopilot content gate revised to the cap. The

### Persona follow-up (investigation only, not implemented)
- The autopilot cannot attach a persona today: `ProjectSpec` has no persona field,
  `InProcessEditorialDriver.create_project` never sets `CarouselProject.persona_id`, and the
  automation start input carries none.
- Passing one at start would not be enough: `StartWorkflowCommand` carries a resolved
  `PersonaProfile` object, but content is built after a resume, and every resume path drops it
  (`BackgroundResumeParams` has no persona; the resume runner hard-codes `persona=None`;
  `build_resume_input` and redrive pass none). With no persona `_score_content_drafts`
  returns `{}`. As traced, the web UI flow has the same gap (persona scores always empty).
- Personas (`PersonaProfileModel`) have no owner link and no default/active flag; no env var
  exists. `carousel_projects.persona_id` (nullable FK) already exists but the workflow never
  reads it. Whether a usable persona row exists in prod was not checked (no prod access in this
  hotfix).
- Recommendation (follow-up ticket, no migration): optional `AUTOPILOT_PERSONA_ID` setting
  (validated to exist); the driver sets `CarouselProject.persona_id`; the engine loads the
  persona from `project.persona_id` when a resume/redrive input has none (fixes the HTTP flow
  too); the HTTP start route persists `body.persona_id`; a test that content after an outline
  approve produces non-empty `persona_scores` and the policy floor applies.
