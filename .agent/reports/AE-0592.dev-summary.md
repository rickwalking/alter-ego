# Developer Completion Report — AE-0592

Ticket: AE-0592 — Periodic check that nginx's Cloudflare ranges are current
Status: Dev Complete
Owner: Pedro

## Summary

A weekly workflow (`.github/workflows/cloudflare-ranges.yml`, Mondays 06:00 UTC, plus `workflow_dispatch`,
`contents: read`) runs `scripts/ci/check_cloudflare_ranges.py`. The script fetches
<https://www.cloudflare.com/ips-v4> and `/ips-v6` over HTTPS and compares them, as networks, with the
`set_real_ip_from` lines of `nginx/nginx.conf.ssl` and `nginx/nginx.conf`, each config on its own.

- Exit 0: both configs list exactly the published ranges.
- Exit 1: a config differs; the log and `$GITHUB_STEP_SUMMARY` list the added and removed ranges per config.
- Exit 2: a list could not be fetched (network error, non-200), is empty or is not a range list, or a config is
  unreadable. The output says "this is NOT a pass".

No GitHub issue and no post (decision in the ticket). No deploy-time fetch, no trust-rule change.
