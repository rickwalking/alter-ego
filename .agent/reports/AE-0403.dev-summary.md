## Decisions

- **Content-step "submit manual fixes":** it uses the existing edits-only revise (`revise("", {editedLocalizedSlides})`, AE-0310). It applies the edits, re-validates, re-interrupts, and never approves.
- **`field_violations`:** a new additive response list. `SlideValidationViolation` gets no new fields, because it is persisted in checkpoints with `extra=forbid`. `validation` is unchanged.
- **Field errors reset per validation run** (a stamp: `lock_version` + `validated_at`, or a refusal counter on the publish page), not per array identity. A state poll keeps the edited fields cleared, and a re-validation with identical violations brings them back.
- **The content-step approve 422** keeps its string `detail`, for backward compatibility.
- **Parentheses stay stripped from edited copy.** This is pinned by the AE-0314 XSS test and is out of scope.
- **Follow-up risk, not changed here:** `phase_feedback[content]` notes accumulate and are never cleared. A content node re-run with prior notes regenerates the drafts, so an edits-only content revise after an earlier feedback revise could regenerate content. Worth its own ticket.
