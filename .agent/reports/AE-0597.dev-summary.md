## Developer Completion Report
Ticket: AE-0597 — A cover switch reopens the final review of an approved or scheduled carousel
Status: In Development (stacked on AE-0594 / PR #338; the lead pushes and opens the PR)

### Summary
Pedro's decision (2026-11-02). A slide-1 cover switch (picker `PUT /cover`, the website generation's
auto-switch, the GrokBot cover, `PUT /hook-photo`) on an approved or scheduled carousel no longer refuses.
It drops the approval in the same commit as the slide-1 write and the needs-republish marker: the row
becomes `draft` at `final_review / awaiting_human`, and the LangGraph checkpoint parked at `approved_hold`
is resumed with a new internal action `reopen_review` that routes back to the `final_review` interrupt (no
phase re-run). The checkpoint is reopened first, then the row commits. The slides re-render; a fresh approve
restores `approved_for_publish`. Published carousels keep the AE-0594 refusal.

Autopilot: a scheduled run moves `scheduled -> reworking` with `scheduled_at` kept (new allowed transition,
reason `cover_review_reopened`); the worker's normal final-review stop sends the review again at the new
lock version (the AE-0594 path; the API layer composes the hook, editorial never imports autopilot).
Approving that review approves final review, then schedules the run at the kept time.

### Missed slot (existing scheduler behaviour): expire, never roll forward
`ScheduledPublishSweep._fire`, `backend/src/rag_backend/modules/autopilot/application/scheduled_publish.py:85-89`
on the base commit (now lines 99-102, after the row lock was added): a due `scheduled` run whose carousel is no
longer `approved_for_publish` moves to `expired`, reason `schedule_withdrawn` (owner text
`TEXT_SCHEDULE_WITHDRAWN`, `schedule_constants.py`), and nothing is published; a still-approved late run is
published late, never moved to another slot. Followed here: a kept time that passes before the new approve
expires the run (`schedule_withdrawn`), both on the approve tap (`application/kept_slot.py`) and at the due
tick, which now also reads `awaiting_owner` runs with a kept `scheduled_at`; if the owner approved again on
the website the due tick publishes it at that time instead.

### How the race test proves the invariant
`backend/tests/integration/test_reopen_review_race_pg_ae0597.py`, real Postgres, each side on its own
session with its real locks (the real sweep wiring `scheduled_publish_sweep`, the real picker
`cover_pick_service` with the project advisory lock, the lock-version CAS and the release re-read):
- the sweep now locks the carousel row (`SELECT ... FOR UPDATE`) before reading the approval and holds it
  until the run move and the release commit; the switch's CAS UPDATE needs the same row lock;
- forced order 1 (the sweep pauses holding the row): the switch is shown blocked, then finds the carousel
  released and is refused (`cover_switch_requires_review`): slide 1, the approval and the reopen untouched,
  run `publishing`;
- forced order 2 (the switch pauses inside its locked write): the sweep is shown blocked, then finds the
  draft: run `expired` (`schedule_withdrawn`), `is_public` false;
- 8 unpaused races each end in exactly one of the two outcomes;
- a release (`Publicar agora`, an approve's release) waiting on the switch's lock re-reads the row and
  releases nothing (the release now requires `approved_for_publish` in its UPDATE and its read).
Never a release with the new unreviewed cover, never a release of a carousel whose approval was dropped.
Without the sweep's row lock the two forced-order tests fail (the run ends `publish_failed`: only the release
check saved it); without the release check the two release tests fail.
