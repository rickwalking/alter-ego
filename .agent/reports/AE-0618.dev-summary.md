# AE-0618 — dev summary

## Change

The daily recovery scan has a new step, after the two revive steps and before the purge. For each stuck run that never
got the owner's Retry it stages one `content.autopilot.escalation_renotice` outbox event and the `scan_renotified`
ledger marker in one transaction. The worker's notifier reads the event as KIND_ESCALATED and sends it with the keyboard
`status_keyboard()` already chooses. The count goes into Pedro's summary and the scan's done log. Decisions are in the
ticket.

No run state, carousel, lock version or `updated_at` changes. No migration, gate, limit or validator changed.
