# Architecture Plan: AE-0552 — Manual carousel recovery through the queue

**Date:** 2026-10-25
**Status:** Ready for development
**Tier:** T3

## Goal and boundaries

Implement owner/admin Reprocessar for exactly four stuck kinds: dead_letter, retry_wait, stale running with a non-null expired heartbeat, and generating with no active run beyond dispatcher grace. Refuse owner waits, normal queued/unstaged work, fresh running, null heartbeat, busy locks, and unsupported states. Never execute a graph in the web process.

## ADR decision

ADR-0026 is amended by Pedro: PgQueuer priority 1 is a bounded exception for explicit owner recovery; ordinary work remains priority 0, active work is not preempted, and FIFO remains by job id/creation inside each class. A separate maintenance entrypoint carries dispatch-only and full maintenance control payloads; it does not share the carousel entrypoint's concurrency-1 bottleneck.

No application schema change. Payload JSON stores manual origin/priority. PgQueuer owns transport priority. Audit uses existing workflow audit/outbox tables.

## API contracts

- `POST /api/carousels/{project_id}/workflow/reprocess`: owner/admin, `expected_version` and optional `run_id`; 202 queued, 200 existing, 409 stable refusal. GET returns capability, lock version, and current run progress for the workspace.
- `POST /api/generation-runs/{run_id}/reprocess`: admin, optional project expected version; generation-status CAS is the fence when no project exists.
- `POST /api/generation-runs/process`: admin, full maintenance; 202 accepted, 200 already-running, 503 when the control job cannot be enqueued.
- Queue rows add autopilot identity, heartbeat, lock version, staged marker, priority and reprocess capability/refusal. Raw last_error is never exposed.

## Reprocess transaction

1. Authorize, load target state, and return a compatible active manual run as existing before any CAS.
2. For takeover kinds, acquire the complete executor lock-key set (autopilot run plus currently attributed project) without waiting and re-read state; any busy required key is drive_active.
3. CAS project lock_version when present/required, rotate the generation attempt UUID, then CAS generation status or stage the existing adopt/autopilot command with manual metadata and durable successor identity.
4. Retry_wait becomes queued and a conditional queued-job update sets priority and execute_after together. Dead workflow requeues by id; dead autopilot uses the shared recovery path. Stale picked jobs are fenced and cancelled before replacement. Failed-terminal replacements are queryable by the original generation id and capped with NOT EXISTS on the staged manual row.
5. Emit `carousel.reprocess.requested` with actor/project/run/stuck kind/versions only, commit once, then enqueue dispatch-only maintenance. Control-enqueue failure leaves durable work for the normal dispatcher and is reported honestly.

Every attempt-scoped count/status/settlement write and notice decision requires the current attempt UUID, preventing old-handler and ABA writes. `last_phase` and authoritative attempt budgets are preserved; transport retry counters are not domain budgets. Existing panel and Telegram retry delegate to this same recovery implementation.

## Maintenance and locks

- `dispatch:<run_id>` calls `Dispatcher.kick(run_id)` then the idempotent dispatcher pass. It never promotes backlog or runs daily recovery.
- `full` calls the existing 08:05 promotion wrapper, AE-0524/#290 recovery wrapper, and a final dispatcher pass.
- Cron only enqueues the same deduped `full` control job as the manual action. Both paths therefore share one execution, non-blocking session advisory lock, and summary path; a busy claimant does not send a summary.
- The maintenance entrypoint is durable and deduped by mode/run id. PgQueuer insert notification wakes the worker immediately.

## Priority and positions

`PgQueuerJobQueue` reads priority from run payload and uses `update_priority`, which cannot demote a manual job. A manual queued job is accelerated with PgQueuer's existing job model; missing jobs are enqueued immediately. Two manual jobs remain FIFO within priority 1.

One pure position/ETA module is used by Telegram and the panel: current running first; priority descending; dispatched jobs by job id; then undispatched work by creation/run id within the same priority. Retry eligibility uses next_attempt_at. ETA subtracts elapsed running time, clamps at zero, advances to retry_wait eligibility when needed, and stays documented as approximate. Retry_wait positions remain hidden in the panel, never #0.

## Board and UI

- A shared autopilot unstaged query feeds Telegram and the panel; generation rows win dedupe races. Unstaged rows have no generation-run-only actions until staged.
- Non-autopilot generating orphans appear as stuck synthetic project rows; abandoned autopilot rows past dispatcher grace can be reprocessed. Positions use the same pure function as Telegram.
- Running heartbeat comes from the attributed carousel project, not generation updated_at. Queued rows never show stale heartbeat as live progress.
- One presentational action component supplies theme-qualified accessible labels and inline confirmations for Cancel/Discard. Polling sets a terminal 403 guard and cleans interval/focus listeners.
- Workspace composes one reprocess hook before the failed-state early return, refreshes on acceptance, and shows queued → running → safe failure states without treating queued time as executing.

## Safety follow-ups

- `owner_queue_cancelled` returns no notice kind; audit/outbox remains and other failures still notify.
- Recovery failure metadata is whitelisted: exception type plus optional DBAPI class/SQLSTATE. Never call `str(exc)` or include SQL/params/exc_info in the owner summary or item log.
- Move `mark_recovery_attempt` to queue_bridge module scope after #290 lands; retain local import only if an import smoke test proves a cycle, documented with the exact edge.

## Testing

Unit: classifier, priority/ETA, board mapping, notices, safe reasons, UI rows/actions/hooks. Integration: every stuck/refusal, owner/admin/reviewer auth, double-click/CAS race, cap/backlog, audit, maintenance-vs-scheduled races, unstaged/heartbeat API, PgQueuer priority/acceleration, SQLAlchemy parameter safety, and import smoke. Full backend/frontend gates and integrity; mutation only on PR CI.

## Rollout and rollback

Normal PR deployment with the existing worker. No migration or feature flag. Revert restores ordinary priority and removes manual actions; already queued manual rows retain valid payloads and are dispatched as ordinary work.
